## 3. 🔴 별자리 히어로 — 데이터 계약

> **이 절이 이 문서의 핵심입니다.** 여기 적힌 규칙은 전부 **결정론적**입니다. 같은 입력·같은 뷰포트면 새로고침해도 배치가 **비트 단위로 동일**해야 합니다. 난수 생성기(`Math.random`)는 어디에도 쓰지 않습니다.

### 3.1 입력 데이터

**소스: 기존 `public/posts-data.json` 그대로.** 히어로 전용 데이터 파일을 새로 만들지 않습니다(홈이 이미 이 파일을 읽으므로 추가 네트워크 비용 0).

사용하는 필드:

| 필드 | 용도 | 현재 존재 |
|------|------|:---:|
| `slug` | 링크 목적지, 해시 시드(동점 정렬·지터) | ✅ |
| `title` | 미리보기 카드, 대체 목록 링크 텍스트 | ✅ |
| `date` (`YYYY-MM-DD`) | x좌표(압축 시간축), 발행 순위 | ✅ |
| `category` (`Study`/`Survey`/`Activity`) | 별 색 | ✅ |
| `keywords` (태그 배열) | y밴드, 연결선 | ✅ |

**`generatePostsData.ts` 변경: 히어로를 위해서는 불필요.** 41편 전부 `keywords`가 비어 있지 않음을 확인했습니다(0개인 글 없음). 아래 두 건만 **홈 전체를 위해** 필요합니다.

| # | 변경 | 필요 이유 | 우선순위 |
|:---:|------|----------|:---:|
| G1 | `readingMinutes: number` 추가 | 시안이 모든 목록 행·카드에 `N분`을 표시하는데 필드가 없음. WRITING_GUIDE §6.11은 "자동 계산"으로 규정 | **P0** |
| G2 | (선택) `excerpt: string` 추가 | description 보유 1/41. §5.3에서 `featured.json`으로 대체하므로 홈에는 불필요 | P2 |

**G1 산식 (확정)**

```
본문에서 프론트매터·코드펜스(```…```)·이미지 문법을 제거한 뒤 공백 제외 문자 수 C
readingMinutes = max(1, round(C / 500))
```

`500자/분`은 한국어 기술 문서 기준값입니다. `N분`으로만 표기하고 `약`을 붙이지 않습니다(WRITING_GUIDE §3.4).
**G1이 릴리스에 못 들어가면**: 메타 문자열에서 ` · N분` 세그먼트를 통째로 생략합니다. `· 0분`이나 `· -분`을 절대 표시하지 마세요.

### 3.2 좌표 계산

#### (1) 정렬과 순위

```
asc  = posts 오름차순 정렬, 키 = (date, slug)      // 같은 날짜 8쌍이 존재 → slug로 동점 해소 필수
rank = 최신순 인덱스 (0 = 가장 최근 글, 40 = 가장 오래된 글)
```

#### (2) x = 압축 시간축 (M1 — 시안의 선형 시간축을 대체)

선형 시간축이 실패하는 이유(실측):

| 지표 | 선형 시간축 | 압축 시간축 |
|------|:---:|:---:|
| 좌측 150px(전체의 14%) 안의 별 수 | **32 / 41** | 17 / 41 |
| 이웃 간 최소 x 거리 (플롯 폭 1060px) | **0.00px** | 0.00px* |
| x 분포(106px 구간별) | 32,4,1,1,0,0,0,1,0,1,1 | 17,4,4,6,2,1,2,1,1,2,1 |

\* 같은 날짜 8쌍은 어떤 시간축에서도 x가 같습니다 → (4) 분리 패스가 해결합니다.

```js
// 인접 발행 간격을 21일에서 잘라 누적 → 죽은 시간을 압축하되 순서·근접성은 보존
const GAP_CAP = 21;            // 일
let w = [0];
for (let i = 1; i < N; i++)
  w[i] = w[i-1] + Math.min(daysBetween(asc[i-1].date, asc[i].date), GAP_CAP);
const u = w.map(v => v / w[N-1]);        // 0..1
const idealX = i => padL + u[i] * plotW;
```

- 실데이터 총 스팬 882일 → 압축 후 **229단위**. 21일보다 긴 공백 8구간(46/79/56/171/182/190/73일 등)이 전부 21로 잘립니다.
- **공백은 사라지지 않습니다.** 2024년 첫 글은 x=72%, 2025년 첫 글은 x=90% 지점에 놓입니다. 즉 우측 28%에 5편만 있는 희소 구간이 그대로 남고, 좌측에는 조밀한 코어가 남습니다. **"2023년에 몰아 쓰고 최근에는 뜸하다"는 사실이 그대로 읽힙니다.**

#### (4) 결정론적 분리 패스 (M1의 나머지 절반)

이상 좌표만으로는 같은 날짜 8쌍이 완전히 겹칩니다. 아래 완화(relaxation)를 **레이아웃당 1회** 실행합니다(매 프레임 아님).

```js
const ITER = 24;
for (let k = 0; k < ITER; k++) {
  for (let a = 0; a < N; a++) for (let b = a+1; b < N; b++) {
    let dx = P[b].x - P[a].x, dy = P[b].y - P[a].y;
    let d = Math.hypot(dx, dy);
    if (d < 1e-6) { dx = 0.6; dy = -0.8; d = 1; }   // 완전 중첩 시 고정 방향으로 분리(결정론 유지)
    if (d < MIN_SEP) {
      const q = (MIN_SEP - d) / 2, ux = dx/d, uy = dy/d;
      P[a].x -= ux*q*0.55; P[a].y -= uy*q;          // x는 0.55로 감쇠 → 시간 순서 보존
      P[b].x += ux*q*0.55; P[b].y += uy*q;
    }
  }
  for (let i = 0; i < N; i++) {                      // 경계 + 시간축 이탈 방지
    P[i].x = clamp(P[i].x, max(padL, idealX(i)-28), min(W-padR, idealX(i)+28));
    P[i].y = clamp(P[i].y, padT, H-padB);
  }
}
```

| 뷰포트 · 플롯 영역 | `MIN_SEP` | 24회 후 실측 최소 간격 |
|------|:---:|:---:|
| xl 1180×480, 플롯 x 700~1132 (텍스트 회피) | 16 | **16.00px** ✅ |
| xl 1180×480, 플롯 전폭 | 16 | **16.00px** ✅ |
| lg 976×440, 플롯 x 560~936 | 15 | **15.00px** ✅ |
| md 768×420, 전폭(텍스트 아래 스크림) | 14 | **14.00px** ✅ |
| sm 390×130 전용 밴드 | 11 | **10.97px** ⚠️ 목표에 0.03px 미달 — 허용 |

- 비용: 820쌍 × 24회 = 19,680회 거리 계산. **0.3~0.8ms, 레이아웃당 1회.** 리사이즈는 150ms 디바운스 후 재실행.
- **x 이탈 상한 28px** 제약을 걸어도 전 케이스가 수렴합니다. 이 제약이 있어야 연도 눈금과 별 위치가 어긋나지 않습니다.

#### (5) 플롯 영역 (padding) — 히어로 텍스트와 겹치지 않게

시안은 canvas를 전폭으로 깔고 텍스트를 그 **위에** 얹습니다. 다크에서는 견디지만 **라이트("페이퍼 위 도표")에서는 잉크 점이 본문 글자 뒤에 깔려 지저분해집니다.** 그래서 lg 이상에서는 **플롯 영역 자체를 텍스트 오른쪽으로 밀어냅니다.**

| bp | canvas | 플롯 `padL / padR / padT / padB` | 비고 |
|----|--------|------|------|
| xl · lg | 전폭(배경 그라데이션은 전폭) | `텍스트블록우측+40 / 48 / 56 / 64` | 별은 우측에만. padB 64는 하단 연도 눈금 자리 |
| md | 전폭 | `40 / 40 / 190 / 48` | 텍스트가 위, 별은 아래. 텍스트 뒤 영역은 스크림 처리 |

- 텍스트 블록 `max-width: 660px`. `padL = 48 + 660 + 40 = 748` (xl 기준), lg는 `32 + 520 + 40 = 592`.
- md에서 텍스트가 별 위에 얹히는 구간은 `linear-gradient(to bottom, var(--color-bg-base) 0%, transparent 100%)` 스크림을 텍스트 블록 뒤에 깝니다(높이 = 텍스트 블록 높이 + 24px).

### 3.4 밝기 · 크기 · 색 (M3 · M4)

#### 왜 시안의 산식을 못 쓰는가

시안: `rec = pow(선형시간_0to1, 1.6)`, `r = 1.6 + rec*3.4`.
실데이터 대입 결과 — **33편의 `선형시간`이 0.15 미만**이라 `rec < 0.04`, 즉 반지름이 전부 **1.66~1.74px**로 붙습니다. 41편 중 33편이 구분 불가능한 같은 점이 되고, "최신일수록 밝다"는 계단이 존재하지 않게 됩니다.

#### 교체: 발행 순위 기반 선형 계단

```js
const rec = 1 - rank / (N - 1);         // rank 0(최신)=1.0 … rank 40(최고참)=0.0
const r      = 1.8 + rec * 3.2;          // 1.8px ~ 5.0px
const alpha  = 0.42 + rec * 0.58;        // 0.42 ~ 1.0
```

| rank | 날짜 | rec | 반지름 | 알파 |
|:---:|------|:---:|:---:|:---:|
| 0 | 2025-05-26 | 1.000 | 5.00px | 1.00 |
| 1 | 2025-03-14 | 0.975 | 4.92px | 0.99 |
| 5 | 2023-09-17 | 0.875 | 4.60px | 0.93 |
| 10 | 2023-04-15 | 0.750 | 4.20px | 0.85 |
| 20 | 2023-02-02 | 0.500 | 3.40px | 0.71 |
| 40 | 2022-12-26 | 0.000 | 1.80px | 0.42 |

날짜 분포와 무관하게 **41단계가 균등하게 벌어집니다.** 새 글이 올라오면 전체 계단이 한 칸씩 밀리므로 유지보수 비용 0입니다.

#### 라이트 모드 형태 계단 (M4)

시안의 임계 `rec > 0.45`(→ 실데이터 4편만 채움)를 **`rec ≥ 0.75`(= rank 0~10, 11편 채움 / 30편 비움)**로 교체합니다.

### 3.6 성능

#### 렌더링 비용과 대책

| 항목 | 시안 그대로 | 확정 명세 |
|------|------------|----------|
| 별 1개당 그리기 | `createRadialGradient` **매 프레임 41회** → 초당 2,460개 그라데이션 객체 할당 (GC 압력) | **스프라이트 프리렌더**: 오프스크린 canvas에 (카테고리 3색 + 골드) × (반지름 8단계) = **32장**을 레이아웃당 1회 그려두고, 프레임당 `drawImage` 41회 |
| 연결선 | 33 stroke | 그대로 (33 stroke는 무시할 비용) |
| 배경 | 매 프레임 `createRadialGradient` | 그라데이션 객체를 **레이아웃당 1회 캐시**, 프레임당 `fillRect`만 |
| DPR | `min(dpr, 2)` | **채택** |
| 오프스크린 | 없음 | `IntersectionObserver`로 히어로가 뷰포트를 벗어나면 rAF 중단, 재진입 시 재개 |
| 탭 비활성 | 없음 | `document.visibilitychange` → `hidden`이면 rAF 중단 |
| 리사이즈 | 매 프레임 `clientWidth` 비교 | `ResizeObserver` + **150ms 디바운스** → 레이아웃 재계산 + 스프라이트 재생성 |
| 무한 루프 | 무한 | **12초 후 자동 정지** (§4.2) — 정상 방문에서 rAF가 도는 시간은 총 12초 |

스프라이트 메모리: 32장 × 64×64 RGBA ≈ **393KB**. 허용 범위입니다.

#### 번들 예산 (계약)

현재 JS 단일 청크 **481KB gzip**(agent-log.md 실측). 별자리가 여기에 더하는 비용:

| 모듈 | 추정 |
|------|------|
| 레이아웃 계산 (정규화·압축축·밴드·해시·완화·링크) | ~2.0KB gzip |
| 렌더러 (다크/라이트 draw·스프라이트·rAF·DPR·IO) | ~3.0KB gzip |
| React 래퍼 + 미리보기 카드 + 대체 목록 | ~1.5KB gzip |
| 데이터 | **+0** (`posts-data.json` 재사용) |
| **합계 (추정)** | **≈ 6.5KB gzip** |

> **수용 기준: 히어로 도입으로 인한 JS 증가분 ≤ 10KB gzip.** 초과하면 구현을 재검토합니다. 외부 라이브러리(three.js·d3·particles류)는 **사용 금지** — 이 예산은 무의존 순수 canvas 2D를 전제로 산정했습니다.

#### CLS

히어로 높이를 §7.1의 `clamp()`로 **미리 예약**합니다. canvas는 `position: absolute; inset: 0`이므로 폰트 스왑·데이터 로드가 레이아웃을 밀지 않습니다. `--font-display` 스왑으로 인한 이름 텍스트의 CLS는 STEP 1의 `size-adjust` 보정 소관입니다.

### 3.7 접근성

> canvas는 스크린리더에게 **아무것도 아닙니다.** 별이 링크로 동작하는 이상 키보드 경로가 반드시 있어야 합니다(WCAG 2.1.1).

#### 구조

```html
<section id="hero" aria-labelledby="hero-name">
  <canvas role="img" aria-label="…§요약문…"></canvas>

  <h1 id="hero-name">김섭우</h1>
  … 직함 · 소개 · 통계 · CTA …

  <!-- 별의 키보드 등가 경로 -->
  <a href="#hero-end" class="skip">별자리 목록 건너뛰기</a>
  <nav aria-label="별자리 — 글 41편">
    <ul class="visually-hidden-until-focus">
      <li><a href="/posts/…">클라이언트 AI의 시대 …</a></li>  <!-- 최신순 41개 -->
    </ul>
  </nav>
  <span id="hero-end" tabindex="-1"></span>
</section>
```

| 항목 | 규격 |
|------|------|
| `canvas` `aria-label` | `글 41편으로 그린 별자리입니다. 가로축은 발행 시점, 선은 같은 태그를 쓴 글끼리 잇습니다. 가장 밝은 별은 2025.05.26에 쓴 가장 최근 글입니다.` |
| 대체 목록 | 41개 `<a>`. **기본은 `.visually-hidden`, 포커스를 받으면 화면에 보입니다**(포커스 이동 경로가 보이지 않으면 안 됨) |
| 건너뛰기 링크 | 목록 앞에 배치. 41개 탭 스톱을 강제하지 않기 위해 **필수** |
| 포커스 ↔ 그래픽 연동 | 목록의 링크가 포커스를 받으면 **해당 별을 호버와 같은 상태로 강조**하고 미리보기 카드를 그 별 위에 표시. 그래픽과 키보드가 같은 것을 가리키게 합니다 |
| 포커스 링 | `--shadow-focus` / 라이트 `--color-focus-ring`. 2px, 오프셋 2px |
| 링크 텍스트 | **글 제목 원문 그대로.** 잘라내지 않습니다(§7.2 — 링크 목록 탐색에서 제목이 유일한 단서) |
| sm/md | canvas `aria-hidden="true"`. 대체 목록도 제거하고, §3.5의 캡션 링크 + 아래 「최근 글」 리스트가 등가 경로를 담당 |
| 색 의존 | 카테고리 범례(색 점 + `Study 30` 텍스트)가 항상 함께 노출 |

`.visually-hidden-until-focus`: `clip-path: inset(50%)` 계열로 숨기고 `:focus-within`에서 해제. `display:none`·`visibility:hidden`은 **금지**(포커스를 못 받습니다).

## 4. 🔴 `prefers-reduced-motion` 명세

> **시안에는 이 대응이 전혀 없습니다**(전체 0회 검출). 아트보드 상단의 "모션 감소 미리보기" 토글은 `state.rm`이라는 시안 내부 상태이고 미디어 쿼리와 연결돼 있지 않습니다. 아래가 확정 명세입니다.

### 4.1 감지 — canvas는 CSS 리셋으로 멈지 않습니다

design.md §5.3의 전역 CSS 리셋(`animation-duration: .01ms !important` …)은 **CSS 애니메이션에만** 적용됩니다. rAF로 도는 canvas는 그대로 돕니다. 따라서 **JS에서도 반드시 읽어야 합니다.**

```js
const mq = matchMedia('(prefers-reduced-motion: reduce)');
mq.addEventListener('change', onMotionPrefChange);   // 런타임 변경도 즉시 반영
```

### 4.2 히어로 별자리 — 저감 모션일 때의 확정 동작

> **결론: 별은 그대로 두고 움직임만 멈춥니다. 정지 이미지로 바꾸지 않습니다.**

근거: 이 그래픽의 정보(어떤 글이 언제·무엇과 이어지는지)는 **정지 상태에서 100% 전달**됩니다. 움직임은 정보를 하나도 나르지 않습니다. 그래서 손실 0으로 전부 끌 수 있습니다.

| 요소 | 기본 | `reduce` |
|------|------|:---:|
| 연결선 그리기 연출 (0→1.4s에 걸쳐 순차 스트로크) | 순차 | **즉시 완성** — 첫 프레임에 33개 선이 전부 그려진 상태 |
| 별 드리프트 (`sin(t)` ±1.1px) | 동작 | **정지** (진폭 0) |
| 최신 별 골드 맥동 (±18%) | 동작 | **정지** (배율 1.0 고정) |
| 포인터 패럴랙스 | 동작 | **정지** (오프셋 0) |
| 호버 시 반지름 ×1.7 · 링 | 240ms 전환 | **즉시 적용** (전환 시간 0, 상태 변화 자체는 유지) |
| 미리보기 카드 `fadeUp` | 120ms | **즉시 표시** (translate 제거, 페이드도 없음) |
| rAF 루프 | 12초간 | **첫 프레임 1장 그리고 즉시 중단.** 이후 호버·포커스·테마 변경·리사이즈 시에만 1프레임 재그리기 |

**핵심**: `reduce`일 때 rAF는 **상시로 돌지 않습니다.** 이벤트 기반 단발 렌더로 전환합니다. 그러면 배터리·CPU 비용도 함께 사라집니다.

### 4.3 기본 모션의 자동 종료 (R2 대응 — `reduce`가 아닌 사용자에게도 적용)

시안의 드리프트·맥동은 **무한 반복**입니다. WCAG 2.2.2는 5초 이상 자동으로 움직이는 콘텐츠에 정지 수단을 요구합니다. 별도의 "정지" 버튼을 히어로에 두는 대신, **스스로 멈추게** 합니다.

```
0 ~ 1.4s     연결선 순차 그리기
1.4 ~ 12.0s  드리프트 + 최신 별 맥동
12.0 ~ 12.4s 진폭을 0으로 감쇠 (ease-out)
12.4s        rAF 중단, 최종 프레임 고정
```

이후의 움직임은 **포인터 패럴랙스와 호버뿐**이며, 둘 다 사용자가 유발하므로 2.2.2 대상이 아닙니다. 포인터가 히어로에 들어오면 rAF를 재개하고, 떠난 뒤 200ms에 rAF를 다시 중단합니다.

> 이 설계는 접근성·배터리·성능을 한 번에 해결합니다. **정상 방문에서 rAF가 도는 시간은 총 12.4초**이고, 그 뒤 홈에 머무르는 동안은 0입니다.

### 4.4 히어로 밖의 애니메이션

| 이름 | 위치 | 기본 | `reduce` |
|------|------|------|:---:|
| `fadeUp` | 미리보기 카드 | 120ms `--ease-out` | 제거 (즉시 표시) |
| 행 호버 배경·전경 색 전환 | 최근 글 6행 | `--dur-base` 160ms | 즉시 |
| 행 좌측 카테고리 바 `scaleY 0→1` | 최근 글 | `--dur-slow` 240ms `--ease-emphasized` | **transform 제거, 항상 `scaleY(1)`이되 기본 상태는 `opacity: 0`** — 즉 호버 시 즉시 나타남 |
| `→` 화살표 `translateX(-8→0)` + 페이드 | 최근 글 | `--dur-slow` | translate 제거, 페이드도 즉시 |
| 카드 `translateY(-3px)` + 그림자 | 읽어볼 만한 글 | `--dur-slow` | **transform 제거.** 보더 색 전환만 남김(호버 피드백은 유지해야 함) |
| 잔디 셀 등장 스태거 (`cellPop`) | 기여 활동 | `--stagger-cell` 8ms × 주 | **제거 — 즉시 전량 표시** |
| 헤더 배경 blur·알파 스크롤 연동 | STEP 1 소유 | — | STEP 1 명세 따름 |
| `scroll-behavior: smooth` | 「글 목록 더 보기」 등 | — | `auto`로 즉시 점프 |

**규칙**: `reduce`에서 **호버 피드백 자체를 없애지 않습니다.** 없애는 것은 *움직임*(transform)이고, *상태 변화*(색·보더·투명도)는 즉시 적용으로 남깁니다. 피드백을 통째로 지우면 "눌리는지 알 수 없는" 인터페이스가 됩니다.

product.md가 지정한 초기 3편(Spatial UX/UI 1·2부, 클라이언트 사이드 AI)은 곧 **최신 3편**입니다. 그대로 두면 같은 화면에 같은 글 3편이 두 번 나옵니다.

```js
const recentSlugs = new Set(recent.map(p => p.slug));   // 위 트랙에 실제로 렌더된 것
const picks = featured.picks
  .filter(f => bySlug.has(f.slug) && !recentSlugs.has(f.slug))
  .slice(0, 3);
```

- 「최근 글」에 이미 있는 글은 건너뛰고 다음 후보로 채웁니다.
- `picks.length === 0`이면 **섹션 전체를 렌더하지 않습니다**(빈 상태를 만들지 않음).
- `picks.length`가 1~2면 그 수만큼만 렌더하고, 설명 문구의 숫자를 그 값으로 씁니다(§10).
- 카드 그리드는 `repeat(auto-fit, minmax(280px, 1fr))` — 2편이어도 레이아웃이 무너지지 않습니다.

#### 이 규칙이 만드는 결과

| 시점 | 실제로 노출되는 3편 |
|------|-------------------|
| **릴리스 시점 (오늘)** | Skeleton Loading · Technical SEO · 아토믹 디자인 패턴 |
| 새 글 3편 이상 발행 후 | Spatial UX/UI 1부 · 2부 · 클라이언트 사이드 AI (최근 글에서 밀려나며 자동 등장) |

> 이건 우회가 아니라 **의도한 동작**입니다. 2트랙의 목적은 "학습 노트에 묻힌 좋은 글을 끌어올리는 것"인데, 오늘 실제로 묻혀 있는 글은 정확히 위 3편입니다. 발행이 재개되면 우선순위 상위 3편이 자연스럽게 올라옵니다. **`featured.json`을 손대지 않아도 됩니다.**

#### 카드 구성 (M6)

| 요소 | 규격 |
|------|------|
| 썸네일 | 높이 **112px** (시안 110 → 4px 스케일 스냅). 6편 전부 썸네일 보유 확인 |
| 카테고리 | 색 점 + 원본 표기(`Survey`/`Study`) |
| 제목 | Pretendard `--fs-md` 15px `--fw-semibold` **3행 클램프** |
| 설명 | **`featured.json`의 `note`**. `description` 필드도, 제목 자르기 폴백도 쓰지 않습니다 |
| 메타 | `YYYY.MM.DD · N분` |

> ❌ 시안의 `desc: POSTS[pi].desc || (title.slice(0,46) + '…')` 폴백은 **제목 바로 아래에 제목의 앞부분을 다시 보여줍니다.** 6편 중 5편에서 이 폴백이 발동합니다. 반드시 `note`로 교체하세요.

### 5.4 `NEW` 배지 (R3)

```js
const isNew = (Date.now() - Date.parse(post.date)) < 14 * 864e5;
```

- **오늘 기준 해당 글 0편.** 배지가 하나도 뜨지 않는 것이 **정상**이며, 그 상태로 릴리스합니다.
- 시안처럼 기준 날짜를 하드코딩하지 마세요. 발행이 재개되는 순간 자동으로 동작합니다.
- 배지는 텍스트(`NEW`)로 표시하고 색만으로 구분하지 않습니다(§7.5).
- 배지가 없다고 제목의 좌측 정렬이 흔들리면 안 됩니다 — 배지는 인라인 플로우에 두고 자리를 예약하지 않습니다.

## 7. 반응형

### 7.1 히어로 높이 (R6)

| bp | 히어로 높이 | 근거 |
|----|------------|------|
| xl | `clamp(440px, 56svh, 560px)` | 첫 화면에 「최근 글」 제목과 1~2행이 걸쳐 보여 스크롤을 유도 |
| lg | `clamp(400px, 54svh, 500px)` | |
| md | `clamp(380px, 52svh, 460px)` | 텍스트가 위, 별이 아래인 단일 컬럼 |
| sm | §7.2 (2존 고정) | |

- `vh`가 아니라 **`svh`**를 씁니다. 모바일 브라우저 툴바 때문에 `vh`는 첫 화면에서 과대 계산됩니다.
- `min-height`가 아니라 명시적 `height` + `overflow: hidden`. canvas가 `inset: 0`으로 채웁니다.
- design.md Part II-D 공통표는 `xl 70vh`를 제시했으나, **56svh로 낮춥니다.** 주 과업이 "30초 안에 읽을 글 파악"이므로 첫 화면이 그래픽으로만 채워지면 손해입니다. 이 편차를 STEP 1 담당에게 공유합니다.

### 7.2 sm(≤767) 히어로 — 2존 구조 (M5)

> 시안 구조의 문제: 모바일에서 별을 텍스트 **뒤에** 깔고 캔버스 전체를 탭 대상으로 만들었습니다. 텍스트 블록이 394px 중 약 297px을 차지하므로 **별이 실제로 보이는 영역은 하단 ~97px뿐**이고, 탭 좌표의 대부분이 CTA 버튼과 겹칩니다. 또 `POSTS.slice(0, 25)`로 **최신 25편만** 쓰는데, 바로 위에 `2022.12부터 · 글 41개`라고 적혀 있어 그래픽과 문장이 서로를 반박합니다.

**확정 구조**

```
┌──────────────────────────────┐  헤더 52px (STEP 1)
├──────────────────────────────┤
│ 김섭우                        │  ┐
│ 프론트엔드 개발자              │  │ 텍스트 존
│ 공부하거나 조사한 내용을 …      │  │ 약 235px
│ 2022.12부터 · 글 41개          │  │
│ [ 전체 글 보기 ]               │  ┘ 48px 버튼 1개
├──────────────────────────────┤
│  ·  ·   ✦    ·      ·    ★   │  별자리 밴드 130px (전폭, 전 41편)
├──────────────────────────────┤
│ 가장 최근 글 · 2025.05.26      │  캡션 링크 (44px 이상)
│ 클라이언트 AI의 시대 …          │
└──────────────────────────────┘
```

| 항목 | 값 |
|------|-----|
| 텍스트 존 | 약 **235px** — 이름 33px(3×11) / 직함 12px / 소개 16px 1~2행 / 통계 12px / CTA 1개 48px |
| 별자리 밴드 | **130px 고정**, 전폭. 좌우 패딩 없음(full-bleed), 플롯 패딩 18/18/14/14 |
| 별 수 | **41편 전량.** 25편으로 줄이지 않습니다 |
| 최소 간격 | `MIN_SEP = 11` → 실측 10.97px |
| 캡션 링크 | 44px 이상, §3.5 카피 |
| 히어로 총 높이 | 235 + 130 = **365px** |
| 첫 화면 점유율 | (52 + 365) / 745 = **56.0%** (iPhone 13/14 세로 가시 뷰포트 745px 기준) ✅ |

> **56% 기준의 정의**: "헤더 + 히어로가 첫 화면에서 차지하는 비율". 시안은 히어로만 계산해 394/760 = 51.8%로 통과했다고 적었지만, 헤더를 넣으면 58.7%로 초과합니다. 위 구조는 헤더 포함 56.0%입니다.

**sm에서 CTA를 1개로 줄이는 이유**: `최신 글 읽기`의 역할을 밴드 아래 캡션 링크가 그대로 대신합니다(같은 목적지·더 많은 정보). 버튼 2개를 세로로 쌓으면 104px을 먹고 56% 예산이 깨집니다.

### 7.3 나머지 섹션

| 섹션 | xl · lg | md | sm |
|------|---------|-----|-----|
| 최근 글 | 전폭 6행, 그리드 `84px 1fr auto` | 6행, 우측 메타를 제목 아래로 내림 | **5행**, 그리드 `64px 1fr`, 날짜·읽기시간은 제목 아래 |

> **첫 화면 점유율을 계산할 때 헤더와 요소 간 간격을 빼먹지 마세요.** 이 누락이 62px(뷰포트의 8.3%)를 숨겼고, 실제로는 목표를 넘고 있었는데 명세상으로는 통과처럼 보였습니다.

### ③ 스프라이트 bake 32 → **25회** (명세 정정)

명세의 32는 **색 4종이 서로 다르다는 전제**였으나, **다크에서 `--color-accent-hover`와 `--color-cat-survey`가 둘 다 `#ffd770`**이라 실제 색은 3종입니다. `Set`으로 거른 25회가 맞습니다.

> ⚠️ **토큰 값 충돌 주의**: 역할이 다른 두 토큰이 한 테마에서 같은 값을 가질 수 있습니다. **색 값으로 캐시 키를 만드는 코드는 자동으로 병합되고, 그건 정상 동작입니다.** 다만 라이트에서는 `#6b4e0b` vs `#7d5c0e`로 갈라지므로 **bake 횟수가 테마마다 다릅니다** — 성능 수치를 잴 때 어느 테마인지 함께 적으세요.

### ④ `개` → `편`을 접근 가능한 이름 3곳에도 적용 — **추인, 되돌리지 마세요**

히어로 nav · 카테고리 칩 2곳 · About 칩 `sr-only`. frontend 근거가 정확합니다 — **화면은 `편`인데 음성만 `개`면 명백한 불일치**이고, `WRITING_GUIDE` §7.3이 *"`aria-label`은 화면에 보이는 텍스트로 시작"*을 요구하므로 **일치시키는 것이 규칙 준수**입니다. 지시 밖이었지만 방향이 맞습니다.

## 13. 구현 순서 제안 (frontend)

1. `generatePostsData.ts`에 `readingMinutes` 추가 → `posts-data.json` 재생성
2. `public/featured.json` 생성 (§5.3)
3. 홈 정적 섹션 3개 구현 — 최근 글 / 읽어볼 만한 글 / 기여 활동. **히어로 자리는 텍스트 + 배경색만.** 이 시점에 홈이 완결된 화면으로 성립해야 합니다(= 히어로 폴백 상태)

6. `prefers-reduced-motion` + rAF 수명주기 (§4)
7. 접근성 대체 목록 + 포커스 ↔ 그래픽 연동 (§3.7)
8. sm 2존 히어로 (§7.2)

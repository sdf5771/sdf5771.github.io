## 1. 주 과업과 화면의 계약

**주 과업**: 41편을 훑어 목표한 글 하나에 도달한다.

성공의 조건은 셋뿐입니다. 나머지 결정은 전부 이 셋에서 파생됩니다.

1. **훑기** — 한 화면에 최대한 많은 글이, 서로 구별되는 형태로 놓인다
2. **걸러내기** — 검색·카테고리·정렬이 즉시 반응하고, **지금 무엇이 걸려 있는지** 항상 보인다
3. **되찾기** — 그 상태가 **URL에 남아** 공유·뒤로가기·새로고침에서 복원된다

3번은 이 프로젝트의 1순위 과제(딥링크 복구)와 같은 요구입니다. 목록 화면만 상태가 휘발되면 일관성이 깨집니다.

**확정 근거 (전부 실측)**

**카드 그리드의 잔여 용도**: 홈의 선별 3편(STEP 2)에만. 목록 화면에서는 쓰지 않습니다.

### 2-4. 정렬 컨트롤 → 회전 토글 **반려**, 2분할 세그먼트로 교체 — 시안 **수정**

시안은 `최신순` 라벨 + 화살표 180° 회전 토글입니다.

**문제**: 라벨 `최신순`이 **현재 상태인지 누르면 될 상태인지 알 수 없습니다.** WRITING_GUIDE §6.1-2(결과를 예고함)를 만족시키려면 `오래된순으로 정렬`이 되어야 하는데, 그러면 §7.3-1(화면에 보이는 텍스트로 시작)과 충돌합니다. 이 충돌은 토글 형태 자체에서 나옵니다.

**교체안**: `최신순` / `오래된순` **두 선택지를 모두 보여주는 세그먼트 컨트롤**.

- 브리프 확정 문구 `정렬: 최신순 / 오래된순`과 오히려 정확히 일치
- 현재 상태가 곧 선택 표시라 라벨 모호성이 사라짐
- aria: `<div role="radiogroup" aria-label="정렬">` + 각 옵션은 링크(§4). 활성 옵션에 `aria-current="true"`
- **부수 효과: 180° 회전 모션이 사라져 §9의 저감 대상이 하나 줄어듭니다**

### 2-5. 카테고리 칩의 비율 막대 → **채택**

시안이 칩 오른쪽에 전체 대비 비율 막대(3~34px)를 붙인 판단은 좋습니다. `Activity 2`가 숫자만으로는 편차가 안 읽히는데 막대가 3px로 남아 "거의 없다"가 한눈에 보입니다. `aria-hidden`이고 개수는 텍스트로 이미 있어 색·길이 단독 전달이 아닙니다(§7.5 준수).

단 **최대폭 34px는 임의값**입니다. §11에서 토큰화 판정.

## 3. 🔴 검색 · 필터 · 정렬 로직 계약

> 이 절이 이 STEP의 핵심입니다. 현재 `usePosts`는 `title`·`category`·`tag`에 **같은 키워드를 AND 완전일치**로 걸어 결과가 **항상 0**입니다. 전면 재작성합니다.

### 3-1. 검색 대상 — 무엇을 뒤지는가

**대상 4필드**: `title` · `keywords[]` · `category` · `description`

**본문은 대상이 아닙니다.** 실측 근거:

| 항목 | 실측 |
|---|---|
| 41편 본문 총 문자 수 | **191,417자** |
| UTF-8 바이트 추정 (한글 혼합) | **380 KB ~ 570 KB** |
| 현재 `posts-data.json` | 15 KB (gzip 2.9 KB) |
| 색인 포함 시 | 약 **25~40배** 증가. gzip 후에도 +100 KB 이상 |
| 현재 JS 번들 | 이미 단일 청크 481 KB gzip |

`/posts` 진입마다 이 파일을 받습니다. 41편 규모에서 본문 검색이 주는 이득보다 비용이 큽니다. `agent-log/product.md` #26이 이미 **백로그**로 판정한 항목이며 이 문서도 같은 결론입니다.

**대신 필수**: 검색 범위를 사용자가 알 수 있어야 합니다. 입력 아래 `제목·태그·카테고리에서 찾아요`를 **항상 노출**합니다(STEP 1 §9 확정 문구). `description`은 1편뿐이라 안내 문구에 넣지 않습니다 — 공짜로 포함하되 광고하지 않습니다.

### 3-2. 매칭 규칙

```
정규화(문자열):
  NFC 정규화 → toLowerCase() → trim() → 내부 연속 공백 1칸으로 축약

토큰화(질의):
  정규화된 질의를 공백으로 분리 → 빈 토큰 제거 → tokens[]
  tokens 가 비면 검색 조건 없음(전체 통과)

포스트 1건의 검색 대상 문자열(haystack):
  정규화( title + "\n" + keywords.join(" ") + "\n" + category + "\n" + description )

일치 판정:
  tokens.every(t => haystack.includes(t))     // 토큰 간 AND, 필드 간 OR
```

| 규칙 | 값 | 근거 |
|---|---|---|
| 부분 일치 | **O** (`includes`) | 한국어는 어절 경계가 없고, `ReactHook_useMemo` 같은 결합 제목이 실재. 단어 경계 매칭이면 `usememo`가 안 잡힘 |
| 대소문자 | **무시** | 태그에 `JavaScript`와 `Javascript`가 **둘 다 존재**. 무시하지 않으면 같은 태그가 갈림 |
| 유니코드 정규화 | **NFC** | macOS 입력기가 NFD를 만들 수 있고, `.md` 파일명·프론트매터 출처가 섞여 있음. 정규화 없으면 `한글`이 안 잡히는 사고가 재현 불가 형태로 발생 |
| 다중 키워드 | **AND** | `react hook`은 "둘 다 있는 글"을 기대. OR이면 react만 있는 14건이 다 나와 필터가 무의미 |
| 필드 간 | **OR** | 토큰이 제목에 있든 태그에 있든 통과. 토큰마다 다른 필드에서 맞아도 됩니다 |
| 최소 길이 | **없음** | 1글자 검색 허용 (`훅`, `합`). 41편 규모에서 결과 폭주 위험 없음 |

**검증 케이스** (구현 후 이 표대로 나와야 합니다)

| 질의 | 기대 결과 | 비고 |
|---|:--:|---|
| `react` | **14건** | 제목 8 + 태그·카테고리 6 |
| `python` | **16건** | |
| `study` | **31건** | 카테고리 30 + 제목에 `(Deep Dive Study)` 1건. **30이 아닙니다** |
| `survey` | 9건 | |

| `javascript` | 5건 | 대소문자 무시가 동작해야 나옴 |

| `react python` | 0건 | AND 동작 확인 (빈 상태 진입) |

| `svelte` | 0건 | 빈 상태 |
| `` (빈 문자열) | 41건 | 검색 조건 없음 |

### 3-3. 초성 검색 → **P0 제외 (반려)**

- 41편 중 한글 포함 제목 34편이지만, 부분 일치가 이미 `브라우` → `브라우저`를 잡습니다. 초성이 추가로 여는 것은 `ㅂㄹㅇㅈ` 입력뿐입니다
- 비용은 작지 않습니다: 한글 음절 분해 + 혼합 토큰(`ㄹㅇ트`) 처리 + **하이라이트 인덱스 매핑**(초성 인덱스 → 원문 인덱스 역산). 마지막 항목이 특히 비쌉니다
- 재검토 조건: 글이 100편을 넘거나, 사용자가 "기억나는데 못 찾는" 사례를 실제로 보고할 때

### 3-4. 정렬 — 🔴 타이브레이커 필수

`date`는 **날짜만 있고 시각이 없습니다.** 그리고 **41편 중 25편이 같은 날짜를 공유**합니다.

| 날짜 | 편수 |
|---|:--:|
| 2023-04-13 | 5 |
| 2023-02-26 | 4 |
| 2023-01-10 | 4 |
| 2022-12-27 | 4 |
| 그 외 4개 날짜 | 각 2 |

날짜만으로 정렬하면 **같은 날짜 묶음의 순서가 정의되지 않습니다.** 페이지 경계에 그 묶음이 걸리면 페이지를 오가는 사이 **같은 글이 두 번 보이거나 한 편이 사라질 수 있습니다.**

```
정렬 키 = [date, slug]
  최신순(desc)    : date 내림차순, 동률이면 slug 내림차순
  오래된순(asc)   : date 오름차순, 동률이면 slug 오름차순
비교는 localeCompare 가 아니라 문자열 < > 로 충분 (date 는 고정폭 ISO, slug 는 ASCII)
```

`slug`는 41편 전부 고유하므로 전순서가 보장됩니다.

### 3-5. 조합 규칙 — 검색 × 카테고리 × 정렬

```
표시목록 = 정렬( 카테고리필터( 검색필터( 전체 41편 ) ) )
표시페이지 = 표시목록.slice( (page-1)*20, page*20 )
```

- 검색과 카테고리는 **AND**입니다. `?q=python&category=Survey` → Python이면서 Survey인 글
- 카테고리 칩의 **개수 배지는 항상 전체 기준 고정값**(전체 41 / Study 30 / Survey 9 / Activity 2)입니다. 검색어에 따라 바뀌지 않습니다
  - 근거: 배지가 요동치면 "이 칩을 누르면 몇 개가 나오는가"가 아니라 "지금 몇 개인가"가 되어, 칩이 **필터 선택지가 아니라 결과 표시**로 변질됩니다. 현재 결과 수는 목록 헤더가 이미 말합니다
- 정렬은 결과 집합에만 작용하며 필터에 영향을 주지 않습니다
- **조건이 하나라도 바뀌면 `page`를 1로 되돌립니다** (§4-3)

### 3-6. 하이라이트 — 🔴 시안 **수정**

시안은 **제목만** 하이라이트합니다. 실측하면 이게 깨집니다.

| 질의 | 결과 | 그중 제목에 일치 문자열이 **없는** 행 |
|---|:--:|:--:|
| `react` | 14건 | **6건** |
| `browser` | 3건 | **3건 (전부)** |
| `hooks` | 3건 | **3건 (전부)** |
| `typescript` | 5건 | 3건 |

`browser`를 검색하면 **세 행 모두 아무 데도 강조가 없습니다.** 사용자 입장에서 "왜 이게 결과인가"를 알 수 없습니다.

**확정 규칙**

1. **제목** — 각 토큰의 모든 출현 구간을 `<mark>`로 감쌉니다
2. **태그 칩** — 토큰이 포함된 태그 칩에 액센트 처리(§5-1 태그 칩 상태표)
3. **🔴 일치한 태그가 노출 3개 밖에 있으면 앞으로 끌어올립니다** — 일치 태그를 먼저 배치하고 남은 자리를 원래 순서로 채웁니다. `+N` 개수는 그에 맞춰 재계산
   - 실측: `webxr`·`browser`·`nextjs` 검색 시 각 1건이 숨은 태그에서만 일치. 이 규칙이 없으면 그 행은 영구히 이유 불명
4. **카테고리 칩(행 우측)** — 토큰이 카테고리명과 일치하면 액센트 처리
5. 토큰이 여러 개면 **각각** 독립적으로 위 1~4를 적용

**하이라이트 구현 규칙**

- 요소는 `<mark>`. `<span>` + 배경색이 아닙니다 (시안은 span)
- 스타일: `background: var(--color-accent-subtle); color: var(--color-accent-text); border-radius: var(--radius-xs); padding: 0 1px`
  - 브라우저 기본 `mark` 스타일(노랑 배경 + 검정 글자)을 **반드시 덮어씁니다.** 안 덮으면 다크 모드에서 형광 노랑 블록이 됩니다
- 대비 실측 (§10에 재게재): 라이트 4.81:1 / 다크 7.74:1 — 본문 기준 4.5:1 통과
- **스크린리더**: `<mark>`는 NVDA·VoiceOver 기본 설정에서 낭독되지 않습니다. **그대로 둡니다.** `aria-label`이나 시각 숨김 텍스트로 "일치"를 덧붙이면 제목 한 줄이 3~4토막으로 끊겨 낭독되어 제목을 알아들을 수 없게 됩니다. 일치 사실은 결과 목록에 있다는 것으로 이미 전달됩니다
- 대신 **결과 수를 `aria-live`로 알립니다** (§10-3)

**정규화와 인덱스**: 매칭은 정규화 문자열에서 하지만 **표시는 원문**이어야 합니다. 소문자화는 길이를 바꾸지 않지만 **NFC 정규화는 바꿀 수 있습니다.** 하이라이트 구간을 계산할 때는 `title`을 NFC 정규화한 문자열로 인덱스를 구하고, **그 NFC 문자열을 그대로 렌더**하십시오(원문으로 되돌리지 마십시오). NFC는 사람이 보는 결과가 동일합니다.

### 3-7. 성능 — 디바운스는 어디에 거는가

| 항목 | 판정 |
|---|---|
| 데이터 로딩 | `/posts-data.json`을 **최초 1회만** fetch하고 모듈 레벨(또는 상위 컨텍스트)에 캐시. 현재 `usePosts`는 `filter`·`sort`·`pagination`이 바뀔 때마다 **재요청**합니다 — 이게 가장 큰 낭비입니다 |
| 필터·정렬·페이징 | 순수 파생. `useMemo`로 계산. 41건 × 4필드 = 마이크로초 단위 |
| 입력 → 결과 반영 | **디바운스 없음.** 매 키 입력에 즉시 반영. 41건에 지연을 넣으면 반응이 둔해질 뿐 이득이 없습니다 |
| 입력 → **URL 반영** | **250ms 디바운스 + `replace`** (§4-3). 이유는 URL 히스토리 오염 방지이지 성능이 아닙니다 |
| 하이라이트 | 표시 중인 20행만 계산 (전체 41건에 미리 계산하지 않음) |

`usePosts`는 **필터를 인자로 받아 fetch하는 훅**에서 **전체를 주는 훅**으로 성격을 바꾸는 편이 단순합니다. 최종 시그니처는 frontend 판단이지만, 위 4줄이 계약입니다.

## 4. 🔴 URL 쿼리 동기화

### 4-1. 판정 — **필수**

| 판단 재료 | 결론 |
|---|---|
| 필터된 목록을 링크로 공유 | `/posts?category=Study`, `/posts?q=react`를 보낼 수 있어야 합니다. 이게 안 되면 "Study 글 모아둔 링크"를 줄 방법이 없습니다 |
| 뒤로가기 | 검색 → 글 상세 → 뒤로가기에서 **검색어가 살아 있어야** 합니다. 없으면 41편 목록 처음으로 돌아가고, 사용자는 검색어를 다시 칩니다 |
| 딥링크 일관성 | 이 프로젝트의 1순위가 딥링크 복구입니다. 목록만 상태가 URL 밖에 있으면 **같은 사이트 안에서 원칙이 갈립니다** |
| 프리렌더 영향 | 쿼리는 클라이언트 처리라 **프리렌더 대상이 늘지 않습니다** (`/posts/index.html` 하나 그대로). 비용이 사실상 0 |
| 이미 있는 것 | `Pagination.tsx`가 이미 `?page=`로 `navigate` 합니다. 나머지 3개만 같은 방식으로 맞추면 됩니다 |

### 4-2. 파라미터 규격

| 키 | 값 | 기본값 | 기본값일 때 |
|---|---|---|---|
| `q` | 검색어 원문 (`encodeURIComponent`) | `""` | **키 자체를 뺍니다** |
| `category` | `Study` \| `Survey` \| `Activity` — **저장된 대소문자 그대로** | 전체 | **키 자체를 뺍니다** |
| `sort` | `oldest` | `latest` | **키 자체를 뺍니다** |
| `page` | `2` 이상의 정수 | `1` | **키 자체를 뺍니다** |

**기본값은 URL에 쓰지 않습니다.** `/posts?q=&category=&sort=latest&page=1`가 아니라 `/posts`가 정규형입니다. 링크를 붙여넣을 때 지저분하고, 같은 화면에 URL이 여러 개 생기는 것을 막습니다.

`sort` 값이 `desc/asc`가 아니라 `latest/oldest`인 이유: 사용자에게 보이는 URL은 UI 라벨(`최신순`/`오래된순`)과 대응해야 읽힙니다. 내부 정렬 방향과는 별개입니다.

**예시**

```
/posts                                    전체 · 최신순 · 1페이지
/posts?category=Study                     Study 30편
/posts?q=react                            검색 14건
/posts?q=react&category=Study             교집합
/posts?sort=oldest&page=2                 오래된순 2페이지
/posts?q=react%20hook                     다중 키워드
```

### 4-3. 히스토리 동작 — 🔴 push와 replace를 구분합니다

| 동작 | 히스토리 | 이유 |
|---|---|---|
| **검색어 입력(타이핑)** | **`replace`**, 250ms 디바운스 | `push`면 `r`·`re`·`rea`·`reac`·`react` 5개 항목이 쌓여 뒤로가기를 5번 눌러야 빠져나옵니다 |
| 검색어 지우기(✕ / 빈 상태 액션) | **`push`** | 명시적 행동. 되돌릴 수 있어야 합니다 |
| 카테고리 칩 선택·해제 | **`push`** | |
| 정렬 변경 | **`push`** | |
| 페이지 이동 | **`push`** | |
| 필터 초기화 | **`push`** | |
| 잘못된 파라미터 정규화(§4-4) | **`replace`** | 사용자가 한 일이 아니므로 히스토리에 남기지 않습니다 |

### 4-4. 잘못된 파라미터 정규화

URL은 사용자가 직접 편집할 수 있고 오래된 링크도 들어옵니다. **절대 빈 화면이나 에러가 되면 안 됩니다.**

| 입력 | 처리 |
|---|---|
| `?category=study` (소문자) | 대소문자 무시 매칭 → `Study`로 정규화하고 URL을 `replace`로 고쳐 씁니다 |
| `?category=Foo` (없는 값) | 파라미터를 버리고 전체로. URL에서 키 제거 (`replace`) |
| `?sort=asc` / 알 수 없는 값 | `asc`는 `oldest`로 해석(관용). 그 외는 기본값으로, 키 제거 |
| `?page=0` · `?page=abc` · 음수 | `1`로 클램프, 키 제거 |
| `?page=99` (결과 3페이지) | **`totalPages`로 클램프**하고 URL을 `replace`. 빈 목록을 보여주지 않습니다 |
| 결과 0건인데 `?page=2` | `page=1`로 클램프한 뒤 빈 상태 표시 |
| `?q=` (빈 값) | 키 제거 |
| 알 수 없는 키 | **그대로 둡니다** (UTM 등 외부 추적 파라미터를 지우지 않습니다) |

**클램프는 렌더 이후가 아니라 파싱 단계에서** 합니다. `page=99`로 진입해 빈 목록이 한 프레임 그려진 뒤 고쳐지면 깜빡임이 보입니다.

### 4-5. 스크롤 위치

| 전환 | 스크롤 |
|---|---|
| 페이지 이동 (`?page=`) | 목록 헤더(`➜ …`) 상단으로 이동. `behavior`는 §9 참조 |
| 검색어 변경 | **이동하지 않습니다.** 타이핑 중 화면이 뛰면 입력이 방해받습니다 |
| 카테고리·정렬 변경 | 목록 헤더 상단으로 이동 |
| 뒤로가기 | 브라우저 기본 복원에 맡깁니다 (`ScrollRestoration` 사용 시 이 화면은 `manual` 제외) |

### 7-3. 구성

```
[← 이전]  [1] [2] [3]  [다음 →]      1 / 3
```

| 요소 | 규격 |
|---|---|
| 요소 | 전부 `<a href="/posts?…&page=N">` |
| 활성 페이지 | 배경 `--color-accent-fill`, 글자 `--color-accent-onFill`, `aria-current="page"` |
| 비활성 페이지 | 배경 `--color-bg-raised`, 글자 `--color-text-secondary`, 테두리 `--color-border-default` |
| 이전/다음 비활성 | `aria-disabled="true"` + `pointer-events: none` + `opacity: .45`. **`<a>`를 남기되 `href`를 제거** |
| `aria-label` | `이전 페이지` / `다음 페이지` / `3페이지로 이동` (WRITING_GUIDE §6.9) |
| `←` `→` `<<` `>>` | `aria-hidden="true"` |
| `1 / 3` 표시 | 목록 헤더 우측과 페이저 우측 **두 곳** (시안 유지) |
| 결과 1페이지 이하 | 페이저 전체를 **렌더하지 않습니다** |
| 결과 0건 | 페이저 없음 (빈 상태만) |

**`Pagination.tsx` 수정 사항**
- `<button>` + `navigate()` → `<a href>` (§5-2)
- `urlPath` 하나가 아니라 **현재 쿼리를 보존**하고 `page`만 바꿔야 합니다. 현재 코드는 `${urlPath}?page=N`으로 **`q`·`category`·`sort`를 전부 날립니다**

## 9. 🔴 `prefers-reduced-motion` 대응

> **시안에 `@media (prefers-reduced-motion)`이 0회 등장합니다.** 시안에는 수동 미리보기 토글이 있어 *의도*는 있었지만 **OS 설정과 연결돼 있지 않습니다.** STEP 2·3에서도 같은 누락이 반복됐습니다.

### 9-1. 이 화면의 모션 목록과 저감 동작

| # | 모션 | 기본 | `reduce` |
|:--:|---|---|---|
| 1 | 목록 재진입 `fadeUp` (필터·검색·페이지 전환 후) | `translateY(6px)` + `opacity 0→1`, 160ms | **제거.** 즉시 최종 상태 |
| 2 | 빈 상태 진입 `fadeUp` | 동일 | **제거** |
| 3 | 스켈레톤 `shimmer` | `1.4s linear infinite` | **정지 + 그라데이션 자체를 단색으로 교체** (§9-2) |

### 9-2. 스켈레톤 — 🔴 가장 틀리기 쉬운 곳

```css
/* 기본 */
.skeleton {
  background: linear-gradient(90deg,
    var(--color-skeleton-base) 0%,
    var(--color-skeleton-sheen) 50%,
    var(--color-skeleton-base) 100%);
  background-size: 320px 100%;      /* keyframes 이동폭과 반드시 일치 */
  animation: shimmer 1.4s linear infinite;
}

@media (prefers-reduced-motion: reduce) {
  .skeleton {
    animation: none;
    background: var(--color-skeleton-base);   /* ← 그라데이션을 통째로 교체 */
    background-size: auto;
  }
}
```

**`animation: none`만 쓰면 안 됩니다.** 그라데이션이 `background-position: -320px`에서 얼어붙어, 막대마다 밝은 띠가 엉뚱한 위치에 멈춘 상태로 남습니다. 시안의 수동 토글이 정확히 이 결과를 만듭니다.

> **시안 버그**: `background-size: 520px 100%`인데 `@keyframes shimmer`는 `-320px → 320px`를 움직입니다. 이동폭과 그라데이션 폭이 어긋나 sheen이 화면 밖에 있는 구간이 생깁니다. **520 → 320으로 통일**하십시오.

### 9-3. 색·배경 전환을 유지하는 이유

`prefers-reduced-motion`은 **전정 자극(vestibular)** — 위치·크기·회전 변화를 겨냥합니다(WCAG 2.3.3 Animation from Interactions). 색·투명도 전환 160ms는 여기 해당하지 않으며, 제거하면 호버 피드백이 뚝뚝 끊겨 **오히려 상태 파악이 어려워집니다.**

**금지**: 전역 `*, *::before, *::after { animation: none !important; transition: none !important }` 카펫 폭격. 위 스켈레톤 문제가 정확히 이 방식의 결과이고, 필요한 피드백까지 같이 죽습니다. **모션별로 개별 처리하십시오.**

### 9-4. 모션이 사라진 자리를 무엇이 메우는가 — 🔴 필수

필터 전환의 재진입 애니메이션은 "목록이 바뀌었다"는 **유일한 시각 신호**입니다. 저감 모드에서는 그 신호가 사라지고, 스크린리더 사용자는 애초에 받은 적이 없습니다.

**대체 장치**: 목록 헤더의 결과 수를 `aria-live` 영역으로 만듭니다.

```
<div aria-live="polite" aria-atomic="true">
  react · 14개 일치 · 전체 41개 중
</div>
```

- `➜` 등 장식 기호는 이 영역 안에서 `aria-hidden` (WRITING_GUIDE §7.4 — *"`aria-live`에 장식 기호를 넣지 않음"*)
- `polite` (`assertive` 아님). 타이핑 중 낭독이 입력을 끊으면 안 됩니다
- 타이핑마다 발화되지 않도록 **URL 반영과 같은 250ms 디바운스**를 겁니다
- 로딩 중에는 컨테이너 `aria-busy="true"`로 중간 상태 낭독을 억제

### 10-3. 키보드 흐름

```
스킵링크 → 헤더 → [본문] h1 → 검색 입력 → (✕) → 칩 전체 → Study → Survey → Activity
        → 정렬 최신순 → 오래된순 → (조건 해제 ✕들) → (필터 초기화)
        → 행 1 → … → 행 20 → 이전 → 1 → 2 → 3 → 다음 → 푸터
```

- **DOM 순서 = 시각 순서.** 정렬 컨트롤이 `margin-left:auto`로 오른쪽에 있어도 DOM에서는 칩 다음입니다 (시안 구조 유지 — 올바름)
- 검색 입력에서 `Enter`: 폼 제출을 막고(`preventDefault`) 아무것도 하지 않습니다. 이미 실시간 반영되고 있으므로 이동시킬 곳이 없습니다
- 검색 입력에서 `Escape`: 검색어를 지웁니다(`type="search"` 기본 동작과 일치)
- 모바일 오버레이: 포커스 트랩 + ESC + 스크롤 락 + 닫을 때 **검색 아이콘으로 포커스 복귀** (STEP 1 §6-4)
- 20행은 탭 이동이 깁니다. 스킵링크(`본문 바로가기`)가 있으므로 헤더 우회는 가능하고, 페이지네이션으로 가려면 20번 탭해야 하는 것은 **20편이라는 페이지 크기의 정상적인 대가**입니다 (6편이면 페이지를 7번 넘겨야 하므로 더 나쁩니다)

### 10-4. 360px 가로 스크롤 0건

- 칩 행만 `overflow-x: auto`이고, **`<body>`나 페이지 컨테이너는 절대 가로 스크롤이 생기면 안 됩니다**
- 96자 제목: `overflow-wrap: anywhere` 없이도 클램프로 처리되지만, `ReactHook_useContext`처럼 **공백 없는 긴 라틴 문자열**이 있으므로 제목에 `overflow-wrap: anywhere`를 겁니다
- 태그 칩 행은 `flex-wrap: wrap`

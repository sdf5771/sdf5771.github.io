### ①  도트 글리프 성좌 — ✅ 채택

**왜 맞는가.** 브리프가 예시로 준 `성좌에서 떨어져 나온 별 하나`를 정확히 구현하면서, 홈 히어로(41편 = 별, 태그 공유 = 연결선)의 조형 언어를 **다른 의미로 재사용**합니다. 홈은 "이어져 있음", 404는 "끊어짐". 같은 문법으로 반대말을 말하는 구조라 두 화면이 한 시스템으로 읽힙니다.

**격자 충돌 우려는 해소됩니다.** STEP 1이 `Galmuri14` 추가를 반려한 근거는 "11px 그리드와 도트 밀도가 달라 한 화면에서 두 격자가 충돌"이었습니다. 그 규칙은 **비트맵 폰트 렌더링**에 대한 것입니다. 404 글리프는 텍스트가 아니라 **SVG 도형**이므로 어떤 크기에서도 선명하고, 정수배 제약을 받지 않습니다. 다만 시각적 일관을 위해 **셀 피치를 22(= `--fs-pixel-2`)로** 두어 픽셀 축과 정렬합니다 — §4-3.

**조건 3개 (충족해야 채택 유효)**

1. **`--fs-pixel-6` 66px으로 `404`를 텍스트로 쓰는 안과 병용하지 않습니다.** 둘 중 하나만. 도트 성좌를 쓰면 66px 텍스트 `404`는 넣지 않습니다. 같은 정보를 두 조형으로 두 번 말하면 그래픽이 장식으로 격하됩니다.
2. **그래픽 전체는 `aria-hidden="true"`.** 바로 아래 `<h1>이 경로에는 아무것도 없어요`가 상황을 이미 말합니다. 스크린리더가 "404"를 별도로 읽으면 WRITING_GUIDE §6.5가 금지한 `404 NOT FOUND`류 정보가 음성 채널에만 생깁니다. §7.1 원칙 3(본문에 같은 설명이 있으면 `alt=""`)과 정합.
3. **정지 상태 성립 조건 4개** — §4-4. 이탈을 *움직임으로만* 표현하면 저감 모션 사용자에게 정보가 사라집니다.

### ②  라이트 = 잉크 점 도표 — ✅ 채택

**왜 맞는가.** agent-log 3차 확정 16번이 홈 히어로 라이트 컨셉을 "페이퍼 위 천체 도표"로 확정했습니다. 404를 "잉크 점 도표"로 두는 것은 그 컨셉의 직선적 연장이며, 별도 발명이 아닙니다.

**시안이 못 다뤘을 가능성이 높은 지점 — 신규 토큰을 만들지 마세요.** 아래 4개로 전부 해결됩니다.

| 요소 | 토큰 | 라이트 | 다크 | 배경 대비 |
|---|---|---|---|:---:|
| 켜진 도트 | `--color-text-muted` | `#5a6072` | `#7f8aa8` | 4.7 / 5.0 |
| 빈 자리(윤곽) | `--color-border-strong` | `#cfc9ba` | `#2d3551` | 장식 |
| 이탈 별 | `--color-accent-text` | `#7d5c0e` | `#e6a536` | 5.9 / 9.4 |
| 끊어진 연결선 | `--color-hero-link-weak` | `rgba(23,28,43,.20)` | `rgba(230,165,54,.11)` | 장식 |

- 도트는 `aria-hidden` 장식이라 WCAG 대비 요건 대상이 **아닙니다.** 위 수치는 "라이트에서 실제로 보이는가"를 확인한 것이며, 4.7:1이면 종이 위 잉크로 충분히 읽힙니다.
- **이탈 별에 `--color-accent-fill`을 쓰지 마세요.** 다크에서는 값이 같아 티가 안 나지만 라이트에서 2.14:1로 무너집니다 (STEP 1 §3-1 경고).
- **신규 토큰 0건.** 이것이 이 판단을 채택하는 부수적 근거이기도 합니다 — 기존 시스템만으로 성립합니다.

### ③  잘못된 경로 표시 — ✅ 채택, 안전 조건 4개 필수

**왜 맞는가.** WRITING_GUIDE §6.5가 명시적으로 요구합니다(가이드 원문은 `장식 ➜ ~ cd <잘못된경로> — 실제 경로 표시`). 브리프도 동일. 위트의 정확도가 올라가고 디버깅에 유용합니다.

> ⚠️ **기호 교체 (2026-08-01 확정).** `➜`는 Galmuri 서브셋에 **글리프가 없어** 전 화면에서 **`▸`(U+25B8)**로 교체됐습니다. 404의 경로 장식도 `▸ ~ cd <경로>`입니다. 이 문서는 교체 후 표기를 씁니다 — WRITING_GUIDE §6.5 원문의 `➜`보다 이쪽이 우선합니다. 함께 확정된 것: `✕`→`×`, `⌕`→CSS 도트.

**이 자리는 이 사이트에서 유일하게 임의 외부 입력이 화면에 들어가는 곳입니다.** 조건 4개는 §4-6에 전문이 있습니다. 요약:

### 4-6. 🔴 경로 표시 — 안전 규격 전문

```ts
const MAX = 72;

/** location.pathname + search → 화면에 안전하게 표시할 문자열 */
function safeDisplayPath(pathname: string, search: string): string {
  const raw = pathname + search;

  // 1) 디코드는 반드시 try/catch. '%ZZ' 같은 잘못된 인코딩은 URIError를 던집니다.
  let s: string;
  try {
    s = decodeURIComponent(raw);
  } catch {
    s = raw;                         // 디코드 실패 시 인코딩된 원문 그대로 표시
  }

  // 2) 제어문자 + 양방향 제어문자 제거.
  //    U+202E(RTL override) 등이 남으면 뒤따르는 화면 텍스트가 좌우 반전돼 보입니다.
  s = s.replace(/[\u0000-\u001F\u007F-\u009F\u200E\u200F\u202A-\u202E\u2066-\u2069]/g, '');

  // 3) 길이 상한 + 중간 절단 (앞뒤를 남겨 무엇을 치려 했는지 보이게)
  if (s.length > MAX) {
    s = s.slice(0, MAX - 20) + '…' + s.slice(-16);
  }
  return s;
}
```

#### `public/404.html` — `<head>` 인라인 스크립트

**React 마운트 전에 리다이렉트를 끝냅니다.** React를 부팅한 뒤 리다이렉트하면 사용자가 404 화면을 한 번 보고 튕겨 나가는 깜빡임이 생깁니다.

```html
<script>
(function () {
  var p = location.pathname, q = location.search;

  // ② 구 경로 /post?id=<slug> → /posts/<slug>
  //    단수 'post' + id 쿼리일 때만. 신 경로 '/posts/'는 매치되지 않아 루프가 없습니다.
  if (/^\/post\/?$/.test(p)) {
    var m = /[?&]id=([^&]+)/.exec(q);
    if (m) { location.replace('/posts/' + m[1].toLowerCase()); return; }
  }

  // ③ 대문자 slug → 소문자 (STEP 3 확정: 소문자 slug가 정본)
  if (p.indexOf('/posts/') === 0 && p !== p.toLowerCase()) {
    location.replace(p.toLowerCase() + q); return;
  }

  // ④ 그 외: 아무것도 하지 않고 SPA 부팅에 맡깁니다.
})();
</script>
```

| 규칙 | 근거 |
|---|---|
| **`location.replace` 사용** (`href=` 아님) | 히스토리에 404가 남지 않습니다. 뒤로 가기가 404로 돌아오면 사용자가 갇힙니다 |
| **slug 존재 여부를 검증하지 않음** | 404.html은 `posts-data.json`을 읽지 않았습니다. 없는 slug면 새 경로에서 다시 404가 나며, `/posts/x`는 `/post?id=` 패턴이 아니라 **무한 루프가 없습니다** |
| **DOM에 아무것도 쓰지 않음** | §4-6. 이 스크립트가 경로 문자열을 화면에 넣는 유일한 안전 방법은 "넣지 않는 것"입니다 |
| **③에서 이미 소문자면 리다이렉트 금지** | `p !== p.toLowerCase()` 가드가 루프를 막습니다 |
| ①이 정본 | 404 폴백만으로는 **OG 미리보기가 원리상 불가**합니다(크롤러는 JS를 실행하지 않고 404 응답에서 포기). agent-log 확정 |

#### GitHub Pages가 원래 경로를 유지합니다

`404.html`을 서빙할 때 GitHub Pages는 **주소창 URL을 바꾸지 않습니다.** 따라서 `window.location.pathname`이 사용자가 실제로 요청한 경로 그대로입니다. 별도의 쿼리 인코딩 트릭(`?/path` 방식)이 **필요 없습니다** — 쓰지 마세요. 그 방식은 주소창을 오염시키고 §4-6의 표시 로직을 복잡하게 만듭니다.

그 경우 **잔디만 낡고 사이트는 정상 동작합니다.** 화면에 별도 처리를 하지 않는 근거는 §5-5 「미갱신」과 같습니다.

**정정 이력 — 원안(별도 워크플로 + JSON 커밋 + GraphQL)을 폐기한 이유**

> 🔴 **아래는 폐기된 원안입니다. 따라 하지 마세요.** 근거를 남기기 위해서만 적습니다.
>
> | 원안 (agent-log 6차 확정 26) | 판정 |
> |---|---|
> | ~~`.github/workflows/contributions.yml`을 `deploy.yml`과 분리~~ | ❌ 폐기 |
> | ~~주 1회 `public/contributions.json`을 갱신·**커밋**~~ | ❌ 폐기 |
> | ~~GraphQL `contributionsCollection` + 토큰(Actions secret)~~ | ❌ 폐기 |
>
> **① 커밋 방식이 성립하지 않습니다.** `GITHUB_TOKEN`이 만든 커밋은 **다른 워크플로를 트리거하지 않습니다**(Actions의 무한루프 방지 동작). 원안대로면 JSON 커밋은 쌓이는데 `deploy.yml`이 돌지 않아 **사람이 다음에 push할 때까지 배포에 영영 반영되지 않습니다.** 워크플로를 분리하지 않은 것도 같은 이유입니다. 커밋을 없애니 이 함정이 원천적으로 사라지고 리포 히스토리도 늘지 않습니다("매일 커밋하면 365커밋" 걱정 자체가 소멸).
> **② GraphQL이 기본 토큰으로 조회되지 않습니다.** `contributionsCollection`은 사용자 기여 스코프가 필요해 **기본 `GITHUB_TOKEN`으로는 조회되지 않고**, PAT를 쓰면 사용자가 시크릿을 등록해야 합니다. **"설정 없이 간다"는 사용자 약속**과 어긋납니다. 공개 조각의 `data-level`이 원안이 요구한 "4분위 계산은 생성 측 책임"을 그대로 충족합니다.

**로드 방식**

```ts
// 모듈 레벨 Promise 캐시. 홈 → 소개로 이동해도 fetch는 세션당 1회.
let cache: Promise<Contributions> | null = null;

export function loadContributions(): Promise<Contributions> {
  if (!cache) {
    const request = fetch('/contributions.json')
      .then(r => {
        if (!r.ok) throw new Error(String(r.status));
        return r.json() as Promise<unknown>;
      })
      .then(data => { assertContributions(data); return data; });  // 최소 형태 가드

    // 🔴 실패는 캐시하지 않습니다. `cache`가 아직 이 요청일 때만 비웁니다.
    request.catch(() => { if (cache === request) cache = null; });

    cache = request;
  }
  return cache;
}
```

> 🔧 **정정 (구현 반영)** — 이전 판의 ~~`cache ??= fetch(…)`~~ 한 줄은 **거부된 Promise까지 캐시**합니다. 그러면 홈↔소개를 아무리 오가도 같은 거부를 즉시 돌려받아 재시도가 되지 않는데, §5-5의 실패 카드는 `잠시 후 다시 시도해 주세요`라고 말합니다 — 카피가 거짓말이 됩니다. 위 `cache = null`이 그 문장을 사실로 만듭니다.
> `assertContributions`(최소 형태 가드)도 필수입니다. `response.json()`은 무엇이든 돌려줄 수 있고, 타입 단언은 그것을 검사하지 않습니다. 검증 없이 통과시키면 `weeks.slice()`가 **렌더 도중** 터져 React 트리가 그 자리에서 죽습니다. 여기서 던져야 호출부 `.catch`가 받아 정상적인 실패 화면이 됩니다.

### 5-3. 컴포넌트 인터페이스 — props는 **1개뿐**

```tsx
interface ContributionGraphProps {
  /** 섹션 h2에 '$' 터미널 프롬프트를 붙일지. 소개=true, 홈=false. 기본 false */
  showPrompt?: boolean;
}
```

**props를 늘리지 마세요.** 주 수·요약 문구·색·캡션·범례를 props로 열면 두 화면이 갈리는 문을 여는 것입니다. PM 요구("소개와 홈에서 주 수·요약 표기가 다르면 안 된다")를 **구조적으로** 보장하는 방법은 조절할 수 없게 만드는 것입니다.

- 주 수(52/16)는 props가 아니라 **컴포넌트 내부의 `matchMedia`/CSS**가 결정합니다.
- `showPrompt`만 예외인 이유: 소개 화면의 다른 h2가 `$ 자주 쓴 태그`·`$ 연락처`인데 기여 활동만 `$`가 없으면 화면 안에서 불일치합니다. `$`는 `aria-hidden` **장식**이므로 접근 가능한 이름은 양쪽 동일합니다.

**미갱신 상태를 화면에 노출하지 않는 이유 (판정)**

1. `데이터가 오래됐어요`는 사용자에게 **어떤 행동도 주지 못합니다.** WRITING_GUIDE §6.2·§6.3이 요구하는 "다음 행동 1개 이상"을 만들 수 없습니다.
2. 재배포가 멈춘 것은 **사이트 오류가 아니라 저자 사정**입니다. 방문자에게 알릴 성격이 아닙니다. (60일 무활동 시 예약 워크플로가 자동 비활성화되는 경우도 여기 해당합니다 — §5-2 「운영상 알아 둘 것」)
3. **이미 `마지막 활동 {날짜}`가 사실을 그대로 말하고 있습니다.** 오래되면 저절로 드러나며, 그것이 이 사이트가 최신성을 다루는 방식(상대 시간 금지, 절대 날짜 표기 — §3.4)과 정합합니다.

**대신 개발자용 경고만 둡니다.** 사용자 화면에는 변화가 없습니다.

```ts
if (Date.now() - Date.parse(data.generatedAt) > 14 * 864e5) {
  console.warn('[contributions] 데이터가 14일 이상 갱신되지 않았습니다:', data.generatedAt);
}
```

**실패 상태에서 섹션 자체를 숨기지 않습니다.** 캡션 `🌱 자라나라 잔디 잔디`와 제목 `기여 활동`은 남깁니다 — 섹션이 사라지면 레이아웃이 튀고, 재방문 시 "원래 없던 것"으로 오해됩니다.

### 5-6. 확정 카피 · 접근성

| 위치 | 문구 |
|---|---|
| h2 | `기여 활동` (소개에서는 `$ 기여 활동`, `$`는 `aria-hidden`) |
| 캡션 | `🌱 자라나라 잔디 잔디` |

```html

```

- 개별 셀은 **전부 `aria-hidden`**. 371개를 낱개로 읽히면 소음입니다.

- `aria-label` 안의 날짜는 **`YYYY년 M월 D일`** 서술형입니다(§3.4). 화면 표시(`2026.07.26`)와 형식이 다른 것이 정상 — 음성으로 읽히는 문장이기 때문입니다.
- `총 371개 셀`: 53주 × 7일. sm은 16주 × 7 = 112개.
- 이모지 `🌱`은 한 화면 1개 규칙(§3.6) 안에 있습니다 — 소개·홈 어느 화면에도 다른 이모지가 없습니다.

### 6-1. 🔴 404에 검색 입력을 두지 않습니다

### 6-2. 확정 — `검색으로 찾기` 버튼이 **전역 검색 UI를 엽니다**


전부 **STEP 1 §6-4가 이미 만든 것**입니다. 404가 새로 만드는 UI는 **0개**입니다.

**필요한 것은 전역 검색을 여는 공개 API 하나뿐입니다.**

**✅ API 구현 완료 (2026-08-01).** STEP 1이 `useShell()`로 노출했습니다. 그대로 쓰세요.

```tsx
const { openSearch } = useShell();
<button type="button" onClick={() => openSearch()}>검색으로 찾기</button>
```

- 열린 뒤의 동작(포커스 트랩·ESC·스크롤 락·닫을 때 트리거로 포커스 복귀)은 전부 STEP 1 §6-3·6-4 명세를 따릅니다. **404가 다시 구현하지 않습니다.**

- ⚠️ 현재 `usePosts`의 필터는 `title`·`category`·`tag`에 같은 키워드를 **AND 완전일치**로 걸어 결과가 항상 0입니다. 재작성은 STEP 4 태스크입니다.

### 6-3. 검색어 프리필 — P0에서 **하지 않습니다** (제안으로만 남김)

잘못된 경로의 마지막 세그먼트를 검색어로 미리 채우는 안을 검토했으나 반려합니다.

- slug 형식이 `2025-05-26-the-era-of-client-side-ai-your-browser-becomes-…` 입니다. 날짜 접두를 떼고 하이픈을 공백으로 바꿔도 **검색어가 12단어 이상**이 됩니다.
- STEP 4 검색 대상이 `title`·`keywords`·`category`인데 slug 단어들이 제목과 일치한다는 보장이 없습니다. **결과 0건이 나오면 "검색도 안 되네"가 되어 이탈을 오히려 늘립니다.**
- STEP 4의 검색 로직이 확정된 뒤 재검토할 수 있습니다. 그때는 `slug → title` 역인덱스로 **정확 복구**를 하는 편이 프리필보다 낫습니다.

### 7-3. 「자주 쓴 태그」 섹션 (구 「다루는 기술」)

#### 데이터 — 🔴 하드코딩 금지

**빈도를 화면에 적어 넣지 마세요.** 글이 늘면 그 순간 틀립니다. `posts-data.json`에서 **런타임 집계**하거나 빌드 시 산출합니다.

```ts
// §3-3의 정본화가 이미 적용된 posts-data.json 기준
const counts = new Map<string, number>();
for (const p of posts) for (const t of p.keywords) counts.set(t, (counts.get(t) ?? 0) + 1);

const ranked = [...counts]
  .sort((a, b) => b[1] - a[1] || a[0].toLowerCase().localeCompare(b[0].toLowerCase()));
```

**정렬 규칙**: 빈도 **내림차순**, 동점이면 **태그명 사전순(대소문자 무시) 오름차순**. 동점이 있으므로 타이브레이커가 없으면 빌드마다 순서가 흔들립니다.

**노출 개수 — 6개**

| 순위 | 태그 | 빈도 | 비고 |
|:--:|---|:--:|---|
| 1 | `Python` | 16 | |
| 2 | `React` | 14 | |
| 3 | `CodingTest` | 9 | |
| 4 | `Javascript` | **5** | ✅ 병합 완료 (4+1) — 커밋 `1bf8f691` |
| 5 | `Typescript` | 5 | 표기 교정 여부 **U-1** |
| 6 | `Frontend` | **4** | 🔴 **병합 필요** (3+1) — §3-3 |
| — | (7위 이하) | 전부 **3** | `Web·Google·Browser·ReactNative·StateManagement·Hooks` 6-way 동점 |

**자르는 규칙: 동점 그룹 중간에서 자르지 않습니다.** 7위부터 6개가 전부 3회 동점이라 그 안에서 자르면 임의 선택이 됩니다. **6개가 그 규칙을 만족하는 최대 집합**입니다.

> 🔴 **`Front-end` 병합이 이 규칙의 전제입니다.** 병합 전에는 `Frontend`가 3회여서 7위 동점 그룹에 합류하고, 그러면 **6개 절단이 불법이 되어 5개로 줄여야 합니다.** §3-3의 병합을 먼저 끝내세요.

> 브리프는 5개(`… Typescript 5 · Javascript 5`)를 제시했습니다. 5개도 규칙상 유효한 절단점입니다. 6개를 택한 이유는 **`Frontend`가 이 페이지의 주 과업에 가장 직접적인 태그**이기 때문입니다. 5개로 되돌리려면 위 `ranked.slice(0, 5)`만 바꾸면 됩니다 — 사용자 확인 U-2.

## 8. 모션 명세

### 8-1. 🔴 404 그래픽은 **SVG + CSS**입니다. canvas를 쓰지 마세요

**PM 질의: "canvas는 CSS로 안 멈추므로 JS `matchMedia` 필수"라는 STEP 2 결론과 어떻게 정합하는가?**

**→ 404에서는 canvas를 쓰지 않으므로 그 제약이 발생하지 않습니다.** 근거 4가지:

| # | 근거 |
|:--:|---|
| 1 | **요소가 47개뿐입니다.** 홈 히어로는 별 41 + 연결선 33 + 스프라이트 32장 + rAF 루프였습니다. 47개 정적 원에 canvas는 과잉입니다 |
| 2 | **CSS 전역 `prefers-reduced-motion` 리셋이 그대로 먹습니다.** JS `matchMedia` 구독·해제·수명주기 관리가 전부 불필요합니다 |
| 3 | **테마 전환이 자동입니다.** canvas는 STEP 1 §3-1 경고대로 `getComputedStyle`로 색을 다시 읽고 재그리기를 해야 합니다. SVG는 `fill: var(--color-text-muted)` 한 줄이면 끝입니다 |
| 4 | **접근성이 한 줄입니다** — `aria-hidden="true"`. 번들 증가 0KB |

**홈과의 시각적 연결은 유지됩니다.** 사용자는 렌더링 기술을 모릅니다. 조형 언어(도트 별 · 골드 액센트 · 연결선 · 라이트의 잉크 도표)가 같으면 두 화면은 한 시스템으로 읽힙니다.

> **만약 frontend가 canvas를 선택한다면** STEP 2 §4.1이 그대로 적용됩니다 — `matchMedia('(prefers-reduced-motion: reduce)')` + `change` 구독 + rAF 수명주기 관리 + 테마 전환 시 색 재읽기. 그 비용을 감수할 이유가 이 화면에는 없습니다.

### 8-2. 모션 목록 — 시안의 토글 정의를 명세로 확정

**시안 상단의 「모션 감소 미리보기」 토글은 시안 내부 상태이지 미디어 쿼리가 아닙니다.** STEP 2 §4가 같은 구조를 확인했습니다. 아래가 프로덕션 확정 동작입니다.

#### 시안 원문 수식 ✅

```js
drift = 0.6 + Math.sin(time * 0.55) * 0.42     // 범위 [0.18, 1.02]
pulse = 1   + Math.sin(time * 1.7 ) * 0.16     // 범위 [0.84, 1.16]
```

| 수식 | 적용 대상 | 해석 | 주기 |
|---|---|---|:--:|
| `drift` | 이탈 별 **변위** | 원래 자리 → 이탈 방향 벡터에 곱하는 **cell 단위 배율** 🟡 | `2π/0.55` ≈ **11.4s** |
| `pulse` | 이탈 별 **반지름** | `r × pulse` — ±16% 맥동 | `2π/1.7` ≈ **3.7s** |

> 🟡 **`drift`의 단위가 원문에서 확인되지 않았습니다.** `offset = drift × cell`(데스크톱 3.6→20.4px 이동)로 해석했습니다. 원문의 사용처를 보고 다르면 그쪽을 따르세요. `pulse`는 1 중심 ±16%라 **반지름 배율**임이 값 자체로 확정됩니다.
> **`time`은 초 단위**입니다. 두 주기(11.4s · 3.7s)가 §8-3의 12초 예산 안에 정확히 들어오는 것이 그 근거입니다.

#### 확정 동작

| 요소 | 기본 | `reduce` |
|---|---|:---:|
| 이탈 별 표류 | `drift` 수식, 주기 **11.4s** | **정지** — `drift = 0.6`(중앙값) 고정 위치 |
| 이탈 별 맥동 | `pulse` 수식, 주기 **3.7s** | **정지** — `pulse = 1.0` 고정 |
| 도트 반짝임 (`opacity` .55↔1) 🟡 | 주기 **2.4s**, 지연을 인덱스로 분산 | **정지** — `opacity: 1` 고정 |
| 끊어진 연결선 페이드 인 🟡 | 400ms `--ease-out` | **즉시 최종 상태** |
| h1·설명·버튼 진입 | 없음 | 없음 |

**정지 위치는 `drift = 0.6`입니다.** 수식의 중앙값이라 움직임의 평균 위치이고, §4-3 표의 이탈 별 좌표 (380, 63)이 이 값 기준입니다. `drift = 0`(원래 자리)으로 멈추면 별이 격자로 돌아가 **§4-4의 정지 상태 성립 조건 3이 깨집니다.**

**저감 모션에서 정보 손실 0**입니다 — §4-4에서 검증했듯 4개의 정적 요소가 "끊어진 연결"을 전부 전달합니다.

### 8-3. WCAG 2.2.2 — 자동 종료

**시안 수식의 주기를 그대로 CSS 반복 횟수로 옮깁니다.**

```css
/* 표류: 11.4s × 1회 = 11.4s  (drift 주기 2π/0.55) */
animation: starDrift  11.4s ease-in-out 1 both;
/* 맥동:  3.7s × 3회 = 11.1s  (pulse 주기 2π/1.7) */
animation: starPulse   3.7s ease-in-out 3 both;
/* 반짝임: 2.4s × 4회 =  9.6s */
animation: dotTwinkle  2.4s ease-in-out 4 both;
```

전부 **12초 예산 안**에서 끝납니다(최장 11.4s). 이 값은 STEP 2 §4.3이 홈 히어로에 확정한 12.4초와 같은 예산이며, 사이트 전체에서 "자동 모션은 12초 안에 끝난다"가 일관됩니다.

`sin` 곡선을 `ease-in-out` 키프레임으로 근사합니다 — 육안으로 구별되지 않고, rAF 루프·수명주기 관리가 사라집니다(§8-1).

- **무한 반복(`infinite`)을 쓰지 마세요.** WCAG 2.2.2는 5초 이상 자동으로 움직이는 콘텐츠에 정지 수단을 요구합니다. 유한 반복이면 별도 정지 버튼 없이 충족됩니다.
- **12초**는 STEP 2 §4.3이 홈 히어로에 확정한 12.4초와 맞춘 값입니다. 사이트 전체에서 "자동 모션은 12초 안에 끝난다"가 일관됩니다.
- `animation-fill-mode: both` **필수** — 끝난 뒤 최종 프레임에 고정됩니다. 없으면 12초 후 초기값으로 튑니다.
- **CSS 애니메이션이라 rAF 관리가 없습니다.** 홈 히어로처럼 감쇠 로직·루프 중단·포인터 재개를 구현할 필요가 없습니다.

### 8-4. `reduce` 구현

```css
@media (prefers-reduced-motion: reduce) {
  .dot, .escapedStar, .brokenLink { animation: none; }
}
```

**애니메이션은 「기본값에서 출발해 기본값으로 끝나는 진동」으로 설계하세요.** 그러면 `animation: none`일 때 자동으로 올바른 정지 상태가 됩니다. 별도의 `reduce` 전용 스타일이 필요 없습니다.

```css
@keyframes dotTwinkle {
  0%, 100% { opacity: 1; }    /* ← 기본값 = 최종값 */
  50%      { opacity: .55; }
}
```

- 전역 리셋(`design.md` §5.3)에 의존하지 말고 **컴포넌트 CSS에 명시적으로** 쓰세요. 전역 리셋이 `animation-duration: .01ms !important`인 경우 `fill-mode`와의 상호작용이 브라우저마다 미묘하게 다릅니다.
- 런타임 변경(사용자가 OS 설정을 바꿈)도 CSS 미디어 쿼리가 자동으로 처리합니다 — JS 구독 불필요.

## 1. 주 과업과 세 화면의 역할 분담

| 화면 | 주 과업 (한 문장) |
|---|---|
| **A `/tags`** | 이 블로그가 무엇을 다루는지 한 화면에서 파악하고, 관심 있는 주제의 글 목록으로 들어간다 |
| **B `/tags/:tag`** | 한 주제로 묶인 글들을 훑어 그중 하나에 도달한다 |
| **C `/archive`** | 조건 없이 전체를 시기 순서로 훑는다 |

### 1-1. 🔴 `/posts` vs `/archive` — 역할 구분 판정

**둘 다 41편을 보여줍니다.** 한 줄로 구분되지 않으면 하나는 불필요하다는 지적이 맞습니다. 판정은 다음과 같습니다.

> **`/posts`는 조건을 걸어 하나를 찾는 곳이고, `/archive`는 조건 없이 전체를 시기 순서로 훑는 곳입니다.**

| 축 | `/posts` (STEP 4) | `/archive` (이 문서) |
|---|---|---|
| 1차 구조 | **필터링된 결과의 페이지** | **연도** |
| 조건 | 검색 · 카테고리 · 정렬 (URL 상태) | **없음** |
| 분량 | 20편/페이지 · 최대 3페이지 | **41편 전량 · 1페이지** |
| 좌측 슬롯 | 96×64 생성 그래픽 | **날짜 `MM.DD`** |
| 답하는 질문 | "이 조건에 맞는 글이 뭐지" | "언제 뭘 썼지 / 그때 무슨 일이 있었지" |
| 존재 근거 | 아카이브 목적 **1순위 수단** (product.md §143) | 14개월 공백을 **타임라인의 일부로 재맥락화** (product.md §67·§210) |

**판정: 존치. 단 아래 세 규칙을 어기면 즉시 중복이 됩니다.**

| 규칙 | 내용 |
|:--:|---|
| R-1 | **`/archive`에 검색·카테고리 필터·정렬 옵션·페이지네이션을 넣지 않습니다.** 하나라도 넣는 순간 `/posts?sort=oldest`의 열화판이 됩니다 |
| R-2 | **`/posts`에 연도 필터를 넣지 않습니다.** 넣으면 `/archive`가 불필요해집니다 |
| R-3 | **행 컴포넌트를 공유하지 않습니다.** 좌측 축이 다르면(썸네일 vs 날짜) 같은 컴포넌트가 아닙니다 (§8-3) |

**진입 경로**: GNB 4항목(`홈`·`글`·`태그`·`소개`)은 STEP 1 확정이라 건드리지 않습니다. `/archive`는 **`/posts` 목록 헤더 우측의 텍스트 링크 `연도별 보기`** 하나로 들어갑니다.
→ 🔴 이 링크는 STEP 4 문서 §5-1 헤더 줄에 추가돼야 합니다. **이 문서는 STEP 4를 수정하지 않았습니다.** §16-3에 교차 이슈로 올립니다.

## 2. 판단 노트 4건 판정

시안 하단 「이 STEP에서 내린 판단」 4건에 대한 판정입니다. **전건 수정 채택**이며 반려는 없습니다 — 네 판단의 *방향*은 모두 옳고, *실행값*이 실데이터·확정 토큰에서 어긋납니다.

### 2-1. ① 빈도 위계를 크기가 아니라 마디 수(가닥)로 → **수정 채택**

**채택하는 것**: 태그 클라우드(글자 크기 차등)를 반려한 판단, 크기를 2단계로만 두고 정확한 값은 별도 채널이 담당하게 한 이중 위계 구조, 숫자를 항상 병기해 가닥을 못 봐도 정보가 온전하게 한 판단.

**반려하는 주장 — "세어서 읽을 수 있습니다"**

주관적 계수(subitizing)의 한계는 4~7개입니다. 그 위는 순차 계수라 시선 이동 16회가 필요하고, 4px 지그재그 배열에서는 사실상 불가능합니다.
→ **가닥은 길이·질량 지표이지 계수 장치가 아닙니다.** 정확한 수는 항상 옆의 숫자가 담당합니다. 명세도 그렇게 씁니다.

**🔴 실측 결함 3건 — 그대로 구현하면 고장으로 보입니다**

| # | 시안 | 문제 | 확정 |
|:--:|---|---|---|
| 1 | 선이 `left:0; right:0` (카드 폭 전체) | 마디 클러스터가 선의 **4~42%만** 차지합니다. `n=2`(span1, 콘텐츠 144px)면 144px 선 위에 11px 마디 두 개 → **끊긴 줄·로딩 실패로 읽힙니다** | **선 폭 = 마디 클러스터 폭.** 컨테이너를 `width: max-content`로 |
| 2 | `background: i < 3 ? node : nodeDim` | 앞 3개만 밝습니다. **"3"에 아무 의미가 없는데 신호를 만들어냅니다.** 16마디 중 13개가 흐린 색이라 "16편 중 3편"으로 읽힐 여지가 있습니다 | **밝기 분기 삭제.** 전 마디 동일 색 |
| 3 | `nodeDim` 다크 `#5c4a18` on `--color-bg-surface` = **2.18:1** | 위 2번 때문에 마디의 대부분이 이 색인데 **3:1 미달**입니다. 다크 모드에서 Python(16)의 마디 13개가 사실상 안 보입니다 | 2번 해결로 **토큰 자체가 소멸** |

**확정 규격 — 가닥(strand)**

| 속성 | 값 | 근거 |
|---|---|---|
| 마디 | **4×4px 원**, gap **3px** | 전체 폭 = `7n − 3`. `n=16` → **109px**. 모바일 span1 콘텐츠 폭 141px 안에 **23% 여유**로 들어갑니다 |
| | 시안 5px/4px는 `9n−4` = `n=16`에서 **140px** — 141px 안에 **1px 여유**뿐이라 패딩·폰트 변동 하나에 넘칩니다 | |
| 배치 | `flex` · **`flex-wrap: nowrap`** | 시안의 `wrap`은 좁은 카드에서 마디가 2줄이 되며 고정 높이 14px를 넘겨 카드 정렬이 어긋납니다 |
| 지그재그 | `translateY(±3px)` 교대 | 시안 유지 |
| 컨테이너 | `width: max-content; height: 14px; position: relative` | |
| 선 | `position:absolute; left:0; right:0; top:50%; height:1px` — **컨테이너가 max-content이므로 결과적으로 마디 폭과 같아집니다** | |
| 마디 색 | `--color-accent-text` (라이트 **5.65:1** / 다크 **8.71:1**) | 시안 `node` 값과 정확히 일치 → 토큰 치환만 |
| 선 색 | `--color-hero-link-strong` | 시안 `strand`(.28/.28)와 근사. **선은 순수 장식이라 대비 요건 대상이 아닙니다**(정보는 마디·숫자가 나름) |
| 호버 | **가닥은 변하지 않습니다** | 카드 배경·테두리·글자색이 이미 상태를 말합니다 |
| 애니메이션 | **없음** | 27개가 동시에 움직이면 훑기를 방해합니다 (STEP 4 §6-3 R8과 동일 원칙) |
| 접근성 | `aria-hidden="true"` | 시안 유지 ✅ |

**16마디가 카드 폭에 들어가는가 — 실측**

| 뷰포트 | 콘텐츠 폭 계산 | span1 | span2 | `n=16` 가닥 109px |
|---|---|---:|---:|:--:|
| 데스크톱 1180 | `1180 − 64(--space-8×2)` = 1116 / `repeat(6,1fr)` gap 12 → col 176 / 카드 패딩 `--space-4`×2 | **144px** | **332px** | ✅ span1에서도 들어감 |
| 모바일 390 | `390 − 32` = 358 / `repeat(2,1fr)` gap 12 → col 173 / 패딩 16×2 | **141px** | **326px** | ✅ span1에서도 들어감 |

즉 **크기 티어와 무관하게 모든 카드에서 성립**합니다. 티어별 span은 위계 표현을 위해 유지하되, 가닥이 넘칠 걱정은 없습니다.

### 2-1b. 🔴 티어 필터 칩 → **반려. `빈도순 / 이름순` 세그먼트로 교체**

### 2-2. ② 태그 = 성좌를 잇는 선 (홈 히어로와 같은 데이터의 두 표현) → **수정 채택**

**🔴 단 한 문장은 사실이 아니므로 명세에서 뺍니다.**

## 3. 🔴 태그 정규화 계약

STEP 2·4·5가 반복해서 지적한 `Javascript`(4) / `JavaScript`(1) 문제를 여기서 종결합니다. 태그 페이지가 생기는 순간 이건 표기 문제가 아니라 **URL 문제**가 됩니다.

### 3-1. 소유 — **빌드 스크립트**

| 후보 | 판정 | 사유 |
|---|:--:|---|
| **빌드 (`generatePostsData.ts`)** | ✅ **채택** | ①프리렌더 대상 목록을 빌드가 알아야 합니다(§4-4) ②slug 충돌을 **빌드 실패**로 잡을 수 있습니다 ③대표 표기 선정 로직이 클라이언트 번들에서 사라집니다 ④`_series.json` 검증(STEP 3 §10-1)과 같은 자리·같은 방식 |
| 표시 단계(런타임) | ❌ 반려 | 41편 × 3.4태그를 매 렌더 정규화하는 비용은 무시할 만하지만, **프리렌더된 HTML에 이미 결과가 박혀 있어야** 하므로 런타임 단독으로는 성립하지 않습니다 |
| 콘텐츠 수정(md 직접) | 🟡 **병행 권고** | `JavaScript` 1건을 `Javascript`로 고치면 **원천 해결**입니다. 파일 1개 · 1줄. STEP 4 §14-3이 이미 "태그 페이지 P1 전 필수"로 기록했습니다. 다만 정규화는 **재발 방지 안전망**으로 남깁니다 |

### 3-2. 정규화 함수 — STEP 4 §3-2의 것을 재사용합니다

```
normalizeTag(s):
  NFC 정규화 → trim() → 내부 연속 공백 1칸으로 축약 → toLowerCase()
```

**검색(STEP 4 §3-2)이 이미 쓰는 함수와 같은 함수**입니다. 별도로 만들지 마십시오 — 두 곳의 정규화가 갈리면 "검색으로는 찾히는데 태그 페이지에는 없는" 태그가 생깁니다.

### 3-3. slug 규칙

```
tagSlug(s) = normalizeTag(s)
             → 공백을 '-' 로 치환
             → 연속 '-' 를 1개로 축약
             → 앞뒤 '-' 제거
```

| 원문 | `normalizeTag` | **URL** |
|---|---|---|
| `React` | `react` | `/tags/react` |
| `Android XR` | `android xr` | **`/tags/android-xr`** |
| `Vision Pro` | `vision pro` | **`/tags/vision-pro`** |
| `Javascript` · `JavaScript` | `javascript` | **`/tags/javascript`** (두 표기가 **같은 URL로 합쳐집니다** — 의도한 동작) |
| `Front-end` | `front-end` | `/tags/front-end` (1회성 → 인덱스·링크 없음, 페이지는 존재 §4-2) |

**실측 확인 결과**

- **62종** 전부에서 **slug 충돌 0건** (🔴 2026-08-13 실측 정정 — ~~63종~~. 빌드 검증은 그래도 넣습니다)
- 특수문자는 **공백(8종)과 하이픈(1종, `Front-end`)뿐**입니다. `.`·`+`·`#`·`/`·`&`·한글 태그는 **없습니다**
- 따라서 `encodeURIComponent`가 필요한 문자가 slug에 남지 않습니다 → **URL 인코딩 이슈 없음**, 프리렌더 파일 경로에 공백이 들어가지 않음(§4-4의 전제)

> **왜 원문 표기를 URL에 쓰지 않는가**: `/tags/Android%20XR`은 ①파일 시스템 경로에 공백이 들어가 프리렌더·배포 스크립트에서 사고가 나기 쉽고 ②`/tags/Javascript`와 `/tags/JavaScript`가 다른 URL이 되어 같은 목록이 두 주소로 존재하며 ③대소문자 오타에 취약합니다.

### 3-6. 데이터 계약

**① `posts-data.json` — 필드 1개 추가**

```jsonc
{
  "title": "...",
  "keywords": ["Web", "Frontend", "AI", ...],   // 원문 유지 — 절대 건드리지 않음
  "tagSlugs": ["web", "frontend", "ai", ...],   // ← 신규. keywords 와 같은 순서·같은 길이
  ...
}
```

- `keywords`는 **원문 그대로 유지**합니다(글 상세 표시가 이것을 씁니다)
- `tagSlugs[i]`는 `keywords[i]`의 slug입니다. **순서와 길이가 반드시 대응**해야 `/tags/:tag`에서 "현재 태그"를 찾아 강조할 수 있습니다
- 목록 필터는 `p.tagSlugs.includes(slug)` — 런타임 정규화가 필요 없어집니다
- 증가량 약 **+1.7 KB** (gzip 후 무시할 수준)

**② `public/tags-data.json` — 신규**

```jsonc
[
  { "slug": "python", "name": "Python", "count": 16 },
  { "slug": "react",  "name": "React",  "count": 14 },
  ...  // 62종 전부. count 로 인덱스 노출을 거릅니다
]
```

| 항목 | 값 |
|---|---|
| 크기 | 약 **2.8 KB / gzip 약 0.7 KB** (**62종**, `slug`·`name`·`count`만) — 🔴 2026-08-13 정정 (~~2,879 B · 63종~~). 실제 산출물로 확인하십시오 |
| 왜 글 목록(`posts[]`)을 넣지 않는가 | `posts-data.json`에 `tagSlugs`가 있으므로 **중복**입니다. 넣으면 9.7 KB로 3배가 됩니다 |
| 소비처 | `/tags` 인덱스(전부) · `/tags/:tag`의 `자주 쓰는 태그` 칩 · **프리렌더 대상 목록 생성** |
| 정렬 | `count` 내림차순 → `slug` 오름차순 (결정론적) |

**③ 빌드 검증 — 실패시켜야 하는 것** (`_series.json` 검증과 같은 방식)

| 조건 | 처리 |
|---|---|
| 서로 다른 정규화 키가 **같은 slug**를 만듦 | 🔴 **빌드 실패.** 조용히 병합되면 두 태그의 글이 섞입니다 |
| slug가 빈 문자열이 됨 (태그가 공백·기호뿐) | 🔴 **빌드 실패** |
| `tagSlugs.length !== keywords.length` | 🔴 **빌드 실패** |

### 4-1. 세 가지 개념을 분리합니다

시안과 브리프가 뒤섞어 놓은 것을 분리하면 결정이 단순해집니다.

| 개념 | 규칙 | 대상 |
|---|---|---|
| **존재**(페이지가 렌더되는가) | 데이터에 그 slug가 있으면 렌더 | **62종 전부** (🔴 2026-08-13 정정 — ~~63종~~) |
| **노출**(인덱스에 오르고 링크가 걸리는가) | 2회 이상 | **27종** |

### 4-2. 존재 정책 — 1회성 태그도 페이지는 렌더합니다

| 판단 재료 | 결론 |
|---|---|
| 사용자가 `/tags/ai`를 직접 쳤거나 외부에서 들어왔다 | **데이터에 있는데 404를 주는 것은 거짓말입니다.** "링크를 걸지 않는다"는 **노출 정책**이지 **존재 정책**이 아닙니다 |

### 4-3. 1회성 태그 페이지의 화면

정상 목록과 같습니다. 단 두 가지만 다릅니다.

- `자주 쓰는 태그` 칩 줄은 그대로 노출합니다 (여기가 유일한 탈출로입니다)

## 5. 🔴 STEP 3 계약 정합 — 링크되는 태그와 안 되는 태그

> 시안 판단 노트 ③: *"1회성 태그는 글 상세의 태그 줄에는 그대로 남지만 **링크가 걸리지 않습니다**."*
> STEP 3 §4-4: *"링크 없는 태그는 `<span>`으로 렌더하고 **호버 커서를 바꾸지 마세요**."*

**현재 계약에서 두 태그를 구분하는 단서는 「호버 시 커서 모양」 하나뿐입니다.** 정지 상태에서는 구분 불가이고, 터치 기기에서는 호버 자체가 없습니다. **일부만 눌리는 칩 줄은 고장으로 읽힙니다.**

### 5-1. 실측 — 얼마나 자주 섞이는가

| 상황 | 편수 | 비율 |
|---|:--:|:--:|
| 태그가 **전부 링크** | 25편 | 61% |
| **링크·비링크가 섞임** | **12편** | **29%** |
| 태그가 **전부 비링크** | **4편** | **10%** |
| 그중 **노출되는 앞 3개 안에서 섞이는 글** | **10편** | **24%** |

**구체 사례**

| 글 | 태그 | 링크 | 노출 3개 |
|---|:--:|:--:|---|
| `2025-05-26` 클라이언트 AI의 시대… | 14 | 4 | `Web`✅ `Frontend`✅ **`AI`❌** + `+11` |
| `2023-02-26` [Front-end CS] 브라우저 렌더링 프로세스 | 3 | 1 | 1개만 링크 |
| `2023-01-11` [Code refactoring] 원티드 프리온보딩… | 3 | 1 | 1개만 링크 |
| `2024-09-04` MongoDB.local Seoul 2024 | 3 | **0** | **줄 전체가 안 눌림** |
| `2023-04-13` 클라우드, SaaS, IaaS, PasS | 4 | **0** | **줄 전체가 안 눌림** |

`+N`을 펼쳤을 때 갑자기 안 눌리는 칩이 나오는 경우도 여기 포함됩니다.

### 5-2. 확정 — 비링크 태그는 **칩이 아니라 평문**으로 렌더합니다

| | 링크되는 태그 (2회 이상) | 링크되지 않는 태그 (1회성) |
|---|---|---|
| 요소 | `<a href="/tags/<slug>">` | `<span>` |
| 배경 | `--color-bg-raised` | **없음** |
| 테두리 | `1px solid --color-border-default` | **없음** |
| 패딩 | `--space-1` `--space-2` | **없음** (좌우 여백만) |
| 글자색 | `--color-text-secondary` | `--color-text-muted` |
| 호버 | 배경 `--color-accent-subtle` · 테두리 `--color-accent-border` · 글자 `--color-accent-text` | **없음** (커서도 바꾸지 않음) |
| 포커스 | `--color-focus-ring` 2px / offset 2px | 대상 아님 |
| `#` 접두 | 유지 · `aria-hidden` | 유지 · `aria-hidden` |

**왜 "칩 vs 평문"인가**

1. 사이트 전체에 **「칩 = 누를 수 있는 것」이라는 규칙 하나**가 생깁니다. 색만 바꾸면 그 규칙이 안 생기고, 색은 §7.5(색 단독 의존 금지)에도 걸립니다
2. **모양(배경·테두리의 유무)은 색맹·저시력·흑백 인쇄에서도 살아남는 단서**입니다
3. 정지 상태에서 구분됩니다 — 터치 기기에서도 동작합니다
4. 추가 카피가 필요 없습니다. "왜 이건 안 눌리나요"라는 질문 자체가 생기지 않습니다

**부작용과 그 판정**

- 태그 15개짜리 글에서 칩과 평문이 섞여 리듬이 흐트러집니다 → 실측상 **태그 15개 글 2편은 15개 전부가 링크**라 이 케이스는 발생하지 않습니다. 최악은 14개 중 4개 링크인 `2025-05-26` 글이고, 노출은 3개 + `+11`이라 한 줄에 칩 2개 + 평문 1개입니다. 감당 가능합니다
- 전부 비링크인 4편은 태그 줄 전체가 평문이 됩니다 → **그게 사실입니다.** 눌리지 않는 칩 3개보다 정직합니다

### 5-3. 검토했으나 반려한 대안

| 대안 | 판정 | 사유 |
|---|:--:|---|

### 7-3. 행 안의 태그 칩은 **링크가 아닙니다**

STEP 4 §14-4가 남긴 미결 항목입니다. **여기서 확정합니다.**

> *"P0에서는 `<span>`. P1에서 `<a>`로 승격 시 **행 링크 안에 중첩 링크가 생기므로** 행 구조를 그때 바꿔야 합니다."*

| 안 | 판정 | 사유 |
|---|:--:|---|
| **A. 행 전체 `<a>` 유지 + 태그 칩은 계속 `<span>`** | ✅ **채택** | 아래 |
| B. 행 링크 해제 + 제목만 링크 + 태그 칩 개별 링크 | ❌ 반려 | 행 전체 클릭 영역이 사라져 훑기(주 과업 1)가 나빠집니다. 탭 스톱이 행당 1개 → 최대 5개로, 16행이면 **80스톱** |
| C. 태그 `<a>`를 DOM에서 행 밖으로 빼고 grid로 겹침 | ❌ 반려 | 중첩 링크는 무효 HTML이라 우회가 전부 트릭입니다. 클릭 영역이 잘리고 스크린리더 순서가 시각 순서와 어긋납니다 |

**A 채택 근거**

1. 행의 주 과업은 **글로 가는 것**입니다. 태그 이동은 `/tags` 인덱스와 상단 `자주 쓰는 태그` 칩이 전담합니다
2. 이미 사용자는 **태그 페이지 안에** 있습니다. 행 안의 태그를 눌러 다른 태그로 튀는 동선은 목록을 훑는 흐름을 끊습니다
3. STEP 4 §5-1이 P0에서 이미 `<span>`으로 만들어 둔 코드를 그대로 씁니다 — **P1에서 추가 작업이 0**입니다

**계약**: `/posts`와 `/tags/:tag`의 **행 안** 태그 칩은 커서·호버 효과 없는 `<span>`입니다. 링크되는 태그 칩은 **글 상세(STEP 3)와 `/tags` 인덱스**에만 있습니다. 이 두 규칙이 다른 이유는 §5-4의 표에 있습니다.

## 11. 🔴 `prefers-reduced-motion` 대응

> **시안에는 `@media (prefers-reduced-motion)`이 0회 등장합니다.** 상단에 수동 미리보기 토글이 있고 `rm` 상태가 전 모션에 실제로 배선돼 있어 **설계는 있고 트리거만 없는** 상태입니다. STEP 2·3·4·5와 같은 패턴입니다.

**확정: 수동 토글을 제품에 넣지 않습니다.** 이 세 화면에는 canvas가 없으므로 **전부 CSS 미디어쿼리로 처리**하고 JS `matchMedia`는 스크롤 동작 하나에만 씁니다.

### 11-1. 모션 목록과 저감 동작

| # | 화면 | 모션 | 기본 | `reduce` |
|:--:|:--:|---|---|---|
| 1 | A | 태그 카드 호버 `translateY(-3px)` | `--dur-slow` `--ease-emphasized` | **transform 제거.** 즉시 최종 위치 |
| 2 | A | 태그 카드 그림자 `sm → md` | 240ms | **유지** (§11-3) |
| 3 | A | 태그 카드 배경·테두리·글자색 전환 | `--dur-base` `--ease-out` | **유지** |
| 4 | A·B | 세그먼트 컨트롤 배경 전환 | 160ms | **유지** |
| 5 | B | 행 호버 배경·글자색 전환 | 160ms | **유지** |
| 6 | B·C | 행 호버 좌측 바 `scaleY(0→1)` | 240ms | **transform 제거. `opacity` 0→1, 120ms** (STEP 4 §9-1 #6) |
| 7 | B | 행 호버 `→` `translateX(-8→0)` + opacity | 240ms | **transform 제거. opacity만 120ms** (STEP 4 §9-1 #7) |

| 11 | C | 섹션 펼침/접힘 높이 애니메이션 | **없음 (즉시)** | 시안대로 유지. **추가하지 마십시오** |

| 14 | A·B·C | 포커스 링 | 트랜지션 없음 | 변화 없음 |

### 11-2. 연도 접기 표시는 회전이 아니라 문자 교체

```
펼침  ▾  (U+25BE)
접힘  ▸  (U+25B8)
```

- 두 글리프 모두 **Galmuri11·GalmuriMono11 서브셋에 존재**함을 확인했습니다 (§9-2a)
- 회전 대신 문자를 바꾸면 `reduce` 분기 자체가 필요 없어집니다 — **모션이 없으므로 저감할 것도 없습니다**
- `aria-hidden="true"`. 상태는 `aria-expanded`가 나릅니다

### 11-3. 색·그림자 전환을 유지하는 이유

`prefers-reduced-motion`은 **전정 자극**(위치·크기·회전 변화)을 겨냥합니다(WCAG 2.3.3). 색·투명도·그림자 전환 160~240ms는 여기 해당하지 않으며, 제거하면 호버 피드백이 뚝뚝 끊겨 **오히려 상태 파악이 어려워집니다.** STEP 4 §9-3과 같은 판정입니다.

**금지**: 전역 `*, *::before, *::after { animation: none !important; transition: none !important }` 카펫 폭격. 스켈레톤이 얼어붙은 그라데이션 얼룩이 되고(STEP 4 §9-2), 필요한 피드백까지 같이 죽습니다.

### 11-4. 모션이 사라진 자리를 무엇이 메우는가

| 화면 | 변화 | 대체 신호 |
|---|---|---|
| `/tags` 정렬 변경 | 카드 순서만 바뀜(수는 불변) | `aria-current="true"`가 현재 정렬을 말합니다. **`aria-live` 불필요** |
| `/tags/:tag` 정렬 변경 | 행 순서만 바뀜 | 동일. **`aria-live` 불필요** |
| `/archive` 접기 | 섹션 내용 표시/숨김 | **`aria-expanded`가 이미 담당합니다** ✅ |
| `/archive` 연도 앵커 이동 | 스크롤 점프 | 대상 섹션 헤더로 **포커스를 옮깁니다**(`tabindex="-1"` + `.focus()`). `reduce`에서 스크롤이 즉시 점프하면 어디로 갔는지 알 수 없기 때문입니다 |

이 세 화면에는 **결과 수가 바뀌는 조작이 하나도 없습니다.** STEP 4 §9-4의 `aria-live` 장치는 여기에 필요하지 않습니다.

## 1. 시안 검수

### 1-1. ④ 워드마크 2행 락업 — ✅ 검증 통과, 채택

시안 주장: *"한 줄이면 정사각 크롭(중앙 630)에서 양끝이 날아간다. 99px 2행이면 첫 줄 594px."*

`Galmuri11-subset.woff2`의 실제 폰트 메트릭(`unitsPerEm 1200`)으로 직접 계산했습니다.

| 크기 | `Seobisback` | `.log` | 한 줄 전체 | 중앙 안전영역 630px 대비 |
|---:|---:|---:|---:|---|
| 88px | 528.0 | 176.0 | 704.0 | 2행 가능, 여유 과다 |
| **99px** | **594.0** | **198.0** | 792.0 | ✅ **첫 줄 594 < 630 (여유 36px)** |
| 110px | **660.0** | 220.0 | 880.0 | ❌ 첫 줄 660 > 630 — **양끝 잘림** |

**시안의 두 핵심 수치(594px · 660px)가 정확히 일치합니다.** 99px이 630 안에 들어가는 **최대 11 배수**이고, 한 단계 위인 110px은 30px 초과합니다. 판단이 옳습니다.

- 한 줄 전체 폭은 제 계산으로 **792px**입니다(시안 주석의 840px과 다름). 문자 간격(`letter-spacing: 1px` × 13 = 13px)을 더해도 805px입니다. **결론은 동일**하고 오히려 시안이 문제를 약간 과대평가한 것이라 **판정에 영향 없습니다.**
- 축소 내성도 충족: 99px → 300px 미리보기에서 **24.75px**, 200px에서 **16.5px**. 브리프 요구(110~132px)보다 작지만, **2행 락업이 정사각 크롭 생존을 사는 대가**로 타당한 교환입니다. 워드마크가 두 줄이 되면서 세로로 커져 인지 면적은 오히려 늘어납니다.

### 1-2. 🔴 도메인 줄 `GalmuriMono11 26px` — **수정 필요**

**26px은 11의 배수가 아닙니다** (11 × 2.36). `handoff-step1-shell.md` §3-3a 위반입니다.

- 라틴이라 "한글 22px 이상" 규칙은 해당 없음이 맞습니다. 그러나 **11의 정수배 규칙은 문자 종류와 무관**합니다 — 비트맵 격자가 비정수배에서 뭉개지는 문제이지 언어 문제가 아닙니다.
- 26px에서는 도트가 흐려져 픽셀 서체를 쓰는 의미가 사라집니다.

**→ `22px`(11×2)로 변경하세요.**

| 후보 | 판정 |
|---|---|
| **22px** | ✅ **채택.** 26px에서 4px만 줄어 레이아웃 교란이 가장 적습니다 |
| 33px | 27% 커져 워드마크와 위계가 흔들립니다. 도메인 줄은 브리프 우선순위 **4순위(사라져도 무방)**라 키울 이유가 없습니다 |

> 22px은 300px 미리보기에서 5.5px로 사실상 보이지 않지만, **의도된 결과**입니다. 이 줄은 원본 크기(X·Slack 데스크톱)에서만 읽히면 됩니다.

### 1-3. 판단 노트 6건 — **전건 채택**

### 1-5. ⑤ 세로 수치 검산 — **결론 유효, 다만 4px 차이**

텍스트 블록 `top:118px`부터 산술로 쌓았습니다.

```
118  블록 top
+99  워드마크 1행          → 217
 +4  행간 margin           → 221
+99  워드마크 2행          → 320
+26  괘선 margin           → 346
 +3  괘선                  → 349
+22  슬롯 margin           → 371
+168 제목 슬롯             → 539   ← 슬롯 바닥
```

**⚠️ 이 절의 이전 판정("시안 주장 y539는 행간 4px 누락, 실제 y543")은 틀렸습니다.** 근거로 삼은 슬롯 높이 172px이 판단 노트 텍스트의 값이었고, **시안 마크업의 실제 값은 168px**입니다. 행간 `margin-top:4px`는 정상 반영돼 있습니다(워드마크 2행 top 221 = 217+4). **시안 주장 y539가 옳습니다.** 아래는 frontend가 렌더된 DOM에서 실측한 정본입니다.

| | 슬롯 바닥 | 도메인 줄 top | 여유 |
|---|---:|---:|---:|
| 이전 오판 (172px 가정) | ~~543~~ | ~~566~~ | ~~23px~~ |
| **실측 정본 (168px · 22px)** | **539** | **567** | **28px** |

**결론: 겹치지 않습니다. 여유 28px.** 도메인 줄 top이 566이 아니라 **567**인 이유는 원문 마크업에 `line-height`가 없어 `normal`로 렌더되고, GalmuriMono11 22px의 실제 줄높이가 30px이 아니라 **29px**이기 때문입니다. `26→22px` 수정은 그대로 유효하며 여유를 늘립니다.

> ⚠️ 위 계산은 `line-height: 1`을 가정한 것입니다. **frontend는 캡처 전에 렌더된 DOM에서 슬롯 바닥과 도메인 줄 top을 실측해 확인**하세요. 어느 쪽이든 여유가 18px 이상이라 레이아웃이 위태롭지는 않습니다.

## 2. 🔴 PNG 산출 방법 (이 문서의 핵심)

### 2-1. 결론 — **새 devDependency를 추가하지 마세요**

| 안 | 판정 |
|---|---|
| Playwright/Puppeteer를 `devDependencies`에 추가 | ❌ **반려**. 브라우저 바이너리 ~300MB가 `npm install`마다 받아집니다. GitHub Actions 배포가 매번 느려지는데, **얻는 건 이미지 1장**입니다 |
| **`npx` 일회성 실행 또는 수동 캡처** | ✅ **채택** |

**이건 일회성 산출물입니다.** 카드가 바뀔 일은 브랜드가 바뀔 때뿐이고, 그때 다시 한 번 돌리면 됩니다. 영구 의존성을 지불할 이유가 없습니다.

> ⚠️ **글별 카드(41장+)는 이 결론을 그대로 쓰지 마세요.** §3-2에 별도 권고가 있습니다.

### 2-2. 캡처 절차

**① 시안 파일을 캡처용으로 손보기**

```
1. 폰트를 로컬 서브셋으로 교체 (CDN 제거 — 외부 의존 없이 캡처되어야 함)
   @font-face { font-family:'Galmuri11';
                src:url('../../src/assets/fonts/Galmuri11-subset.woff2') format('woff2'); }
   @font-face { font-family:'GalmuriMono11';
                src:url('../../src/assets/fonts/GalmuriMono11-subset.woff2') format('woff2'); }
   Pretendard도 동일하게 로컬 경로로.

2. 도메인 줄 26px → 22px (§1-2)

3. 첫 번째 아트보드(1200×630)를 제외한 나머지를 전부 제거하거나 숨김
   ★300px·200px 축소본 · 메신저 배치 · 정사각 크롭 · 제목 슬롯 토글은
     전부 검증용 참고물입니다. 캡처 대상이 아닙니다.★
```

**② 캡처**

```bash
npx -y playwright@latest screenshot \
  --viewport-size=1200,630 \
  --wait-for-timeout=1500 \
  "file:///.../step8-og-capture.html" public/og/default.png
```

또는 수동: 브라우저에서 열고 **기기 배율 100%**로 아트보드 영역만 캡처.

**필수 조건 4가지**

| # | 조건 | 이유 |
|:--:|---|---|
| 1 | **`deviceScaleFactor: 1`** | 2로 잡히면 2400×1260이 나옵니다. Retina 화면에서 수동 캡처할 때 특히 주의 |
| 2 | **`document.fonts.ready` 대기** | 폰트 로드 전에 찍으면 폴백 서체로 굳습니다. 타임아웃 1.5초 이상 |
| 3 | **`-webkit-font-smoothing: none` 유지** | 픽셀 서체의 안티에일리어싱을 끄는 설정. 빠지면 도트가 흐려진 PNG가 나옵니다 (§4-5) |
| 4 | **배경 불투명** (`omitBackground: false`) | 투명 PNG는 플랫폼마다 예측 불가하게 렌더됩니다 |

**③ 검증·압축**

```bash
file public/og/default.png          # 1200 x 630 확인
ls -la public/og/default.png        # 300KB 이하 확인
npx -y oxipng -o4 public/og/default.png   # 초과 시 무손실 압축
```

- **PNG 고정. JPG 금지** — 크로마 서브샘플링이 네이비 위 골드 도트를 뭉갭니다. 그게 이 카드의 정체성입니다
- 평면 색 위주라 PNG-8(256색)로 100KB 이하가 나올 가능성이 높습니다. 300KB를 넘으면 그라데이션이 과한 것이니 먼저 그쪽을 줄이세요

### 2-3. 메타 태그 (frontend, `index.html`)

```html
<meta property="og:image" content="https://sdf5771.github.io/og/default.png" />
<meta property="og:image:width" content="1200" />
<meta property="og:image:height" content="630" />
<meta name="twitter:card" content="summary_large_image" />
```

- ★`og:image`는 반드시 절대 URL★ — 상대 경로가 이번 문제의 원인이었습니다. 스크레이퍼는 상대 경로를 해석하지 않습니다
- `name=` 이 아니라 **`property=`** (OG 사양)
- `twitter:card`는 `summary` → **`summary_large_image`**. 그래야 1.91:1이 적용됩니다
- `width`/`height`를 주면 스크레이퍼가 이미지를 받기 전에 자리를 잡아 미리보기가 빨리 뜹니다

## 3. 글별 카드 확장 계약

### 3-1. 인터페이스 (한 줄)

> **`renderOgCard({ title }: { title: string }) → PNG`** — 카드의 다른 요소는 전부 고정이고, **제목 슬롯 1000×168px의 텍스트만** 교체합니다.

| | |
|---|---|
| 기본 카드 | ~~`title = '프론트엔드 개발자 김섭우'`~~ → **현재 정본 `title = 'Software Engineer'`** (2026-08-02 자기 표기 변경, §3-3) → `public/og/default.png` |
| 글별 카드 | `title = <글 제목>` → `public/og/posts/<slug>.png` |
| 슬롯 규격 | **1000 × 168px 고정**, Pretendard 700, **2행 클램프**, 3행째 말줄임 |
| ⚠️ 정사각 크롭 여유 | **기본 카드 제목이 좌우 10px밖에 안 남습니다.** 글별 카드에서 1행짜리 짧은 제목이 조금만 길어져도 정사각 크롭에서 잘립니다(2행이면 오히려 안전). 이 태스크에서 함께 다룰 것 |
| 입력 한계 | 실제 글 제목 **최장 96자**. 2행에 약 36자만 들어가므로 **말줄임이 기본 동작** |
| 불변 요소 | 워드마크 2행 락업 · 도메인 줄 · 성좌 · 배경 — 전부 그대로 |

글 상세 `og:image`는 `https://sdf5771.github.io/og/posts/<slug>.png`로 프리렌더가 주입합니다.

### 3-2. ⚠️ 글별 카드는 브라우저 캡처로 가지 마세요

41장 이상을 자동 생성할 때 헤드리스 브라우저를 41번 띄우는 것은 과합니다. **이 카드는 인터랙션이 없는 순수 정지 그래픽**이므로 더 가벼운 경로가 있습니다.

| 방식 | 판단 |
|---|---|
| **단일 SVG로 재구성 → `@resvg/resvg-js`로 래스터** | ★권장. 브라우저 불필요, 폰트를 파일로 임베드해 결정적. 의존성 ~10MB |
| `sharp`의 SVG 입력 | 가능하나 텍스트 렌더링·폰트 처리가 resvg보다 약합니다 |
| Playwright 배치 | 최후 수단. 41회 브라우저 기동 비용 |

→ 프리렌더 태스크 착수 시 **카드를 단일 self-contained SVG로 옮기는 작업을 먼저** 잡으세요. 시안이 이미 SVG+CSS로만 구성돼 있어 전환 비용이 낮습니다.

## 3-3. 🔴 PNG 재생성 필요 (2026-08-02)

사용자가 자기 표기를 바꿨습니다. **제목 슬롯 텍스트가 이미지에 구워져 있어 PNG를 다시 뽑아야 합니다.**

| | 이전 | **확정** |
|---|---|---|
| 제목 슬롯 (구워지는 픽셀) | `프론트엔드 개발자 김섭우` | **`Software Engineer`** |
| `og:image:alt` (대체 텍스트) | (제목 슬롯과 동일) | ~~`Software Engineer`~~ → **`Seobisback.log — Software Engineer`** |

**슬롯에서 이름을 빼는 이유**: 카드에 워드마크 `Seobisback.log`가 이미 있어 `Software Engineer Seobisback`으로 두면 **한 이미지에 이름이 두 번** 나옵니다.

**🔧 `og:image:alt`는 슬롯과 값이 다릅니다 (2026-08-02 정정 — frontend 이의 채택)**
최초 확정에서 alt를 슬롯과 같은 값으로 적었으나, **위 근거는 구워진 픽셀에만 해당합니다.** 「한 이미지에 두 번」은 보이는 면적을 두고 다투는 문제이고 alt는 면적을 쓰지 않습니다. alt는 슬롯이 아니라 **이미지 전체**를 대신하므로, 카드에서 가장 크고 유일한 신원 표시인 워드마크가 빠지면 안 됩니다(WCAG 1.1.1 images of text). 전체 근거는 `WRITING_GUIDE` §3.3a 근거 4 · §7.1 소셜 카드 행.

> 미적용 후속 — **`twitter:image:alt`가 없습니다.** X/트위터는 `og:image:alt`로 폴백하지 않습니다. 이번 스코프 밖이라 손대지 않았고, 다음 `index.html` 작업 때 `og:image:alt`와 같은 값으로 1줄 추가하세요.

**부수 이점** — 슬롯이 **라틴 17자 1행**으로 짧아집니다. 이전 한글 12자보다 폭은 비슷하나 **2행 클램프가 필요 없어져** 축소 시 가독성이 오히려 좋아집니다. 슬롯 규격(1000×172px)·서체(Pretendard 700)·글별 카드 계약(§3-1)은 **전부 그대로**입니다.

전체 카피는 `WRITING_GUIDE` §3.3a.

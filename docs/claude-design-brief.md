## 📖 이 문서를 쓰는 법

이 문서는 **Claude Design에 그대로 복사해 붙여넣는 프롬프트 모음**입니다. 읽는 문서가 아니라 쓰는 문서입니다.

### 순서

```
① 「빈칸 채우기」에서 ⟨ ⟩ 표시된 값을 먼저 확정
        ↓
② STEP 1부터 순서대로 진행. 각 STEP마다:
        [공통 블록] 전문 + [STEP N] 전문을 이어붙여 한 번에 붙여넣기
        ↓
③ 결과를 확인하고 다음 STEP으로
```

### 규칙

- **[공통 블록]은 매 STEP마다 다시 붙여넣습니다.** 대화가 길어지면 앞의 토큰 값이 흐려지고, 그때 Claude Design이 색을 지어내기 시작합니다. 매번 앞에 붙이는 게 가장 확실합니다.
- **STEP을 건너뛰지 마세요.** STEP 1(디자인 시스템 + 전역 셸)이 뒤의 모든 화면의 전제입니다.
- **한 번에 전 화면을 요구하지 마세요.** 화면 수가 많을수록 각 화면의 품질이 떨어집니다.
- STEP 6·7은 선택입니다. STEP 1~5(P0)만으로 첫 릴리스가 가능합니다.

### STEP 구성

| STEP | 뽑는 것 | 우선순위 | 비고 |
|:---:|---------|:---:|------|
| **공통 블록** | (붙여넣기용 컨텍스트) | — | 매 STEP 앞에 반복 |
| **1** | 디자인 시스템 시트 + 전역 셸(GNB·푸터·테마 토글·검색 진입) | P0 | **필수 선행** |
| **2** | 홈 — 별자리 히어로 + 최신/선별 2트랙 + 기여 활동 | P0 | 가장 어려움. 시간 여유 있을 때 |
| **3** | 글 상세 + 상태 변형 4종 | P0 | 41편 전부가 이 화면 |
| **4** | 글 목록 + 검색 결과 + 빈 상태 + 필터 상태 | P0 | 같은 컴포넌트의 상태 묶음 |
| **5** | 404 + 소개(About) | P0 | 404에 비중 |
| **6** | 태그 인덱스 + 태그별 목록 + 연도별 아카이브 | P1 | 2차 릴리스 |
| **7** | 작업 목록 `/works` + 작업 상세 `/works/:slug` | P1 / P2 | ✅ **착수 가능** (경력기술서 반영 완료, 15건 확정) |

## ✏️ 빈칸 채우기 (붙여넣기 전에 확정하세요)

프롬프트 안에 `⟨ ⟩`로 표시된 곳입니다. 채우지 않으면 Claude Design이 지어냅니다.

| # | 빈칸 | 현재 잠정값 | 확정 필요 이유 |
|---|------|------------|--------------|
| 1 | `⟨워드마크⟩` | `섭우.log` | 전 화면 헤더에 들어감. `Seobisback's Blog` 유지도 선택지 (design.md 결정 7) |
| 2 | `⟨히어로 한 줄 소개⟩` | `더 나은 서비스를 만드는 방법을 고민합니다` | 홈의 첫인상 문장 |
| 3 | `⟨선별 글 3편⟩` | Spatial UX/UI 1부·2부, 클라이언트 사이드 AI | product.md §2-3 초기값. 바꾸려면 지금 |
| 4 | `⟨카테고리 표기⟩` | 원본 유지 (`Study` `Survey` `Activity`) | 한국어(`학습`·`조사`·`활동`)로 바꿀지. **데이터는 무변경, 표시만** |
| 5 | `⟨Notion 링크 노출⟩` | 노출 (About 하단 `이력서 보기 ↗`) | product.md §13-5 권고 = PDF는 리포에 올리지 않고 Notion 링크로 |
| 6 | `⟨코딩, 좋아? 계승⟩` | **미사용** | 사용자 본인 문구(`코.딩.좋.아?`). 히어로에 쓸지 (WRITING_GUIDE §11-1) |
| 7 | 작업 항목 | ✅ **확정 — 15건** | 경력기술서 반영 완료. 익명 표기안이 STEP 7 안에 실데이터로 들어가 있어 **채울 것이 없습니다** |

> 1~6이 정해지지 않아도 STEP 1~5는 진행 가능합니다. 잠정값 그대로 두고 시안을 뽑은 뒤 문구만 교체해도 레이아웃은 유효합니다.

# 📋 [공통 블록] — 매 STEP 앞에 붙여넣기

```
아래는 개인 기술 블로그 리디자인 프로젝트의 확정된 배경과 디자인 시스템입니다.
여기 적힌 값은 전부 확정 사항입니다. 새로 지어내지 말고 그대로 사용해 주세요.

═══════════════════════════════════════
1. 이 사이트가 무엇인가
═══════════════════════════════════════

- 한국인 프론트엔드 개발자 김섭우(@sdf5771)의 개인 기술 블로그. 도메인 sdf5771.github.io
- 2022년 12월부터 운영, 한국어 글 41편. GitHub Pages 정적 호스팅 (서버·SSR 없음)
- 사이트 전체 언어는 한국어입니다.

목적 우선순위 (이 순서가 모든 판단의 기준):
  1순위 포트폴리오 — "이런 걸 하는 사람"임을 보여준다
  2순위 개인 아카이브 — 내가 쓴 글을 내가 다시 찾는다
  3순위 트래픽 — 목표가 아님. 구독·댓글·조회수·좋아요를 넣지 마세요

★ 가장 중요한 제약 ★
이 사람은 재직 중이며 이직에 열려 있지만, 구직 의도가 노골적으로 드러나기를
원하지 않습니다. 현재 직장 동료가 이 사이트를 봤을 때 "이직 준비하는구나"로
읽히면 실패입니다.

따라서 다음은 절대 넣지 마세요:
  ✗ "OPEN TO WORK" 배지, 구직 상태 표시
  ✗ 이력서 다운로드 버튼 (홈 히어로의 주/보조 CTA 자리)
  ✗ 스킬 레벨 바, "React Lv.9", 숙련도 %, 별점
  ✗ 채용 문의 CTA
  ✗ "포트폴리오"라는 단어 (UI 라벨에서)

대신: 작업물과 최신성이 스스로 말하게 합니다. 요청하지 않고 보여줍니다.

═══════════════════════════════════════
2. 기존 자료와의 관계
═══════════════════════════════════════

같은 Claude Design 프로젝트에 이미 두 파일이 있습니다:
  · Blog Home Concepts.dc.html — 홈 시안 3종 (ARCADE / TERMINAL / EDITORIAL)
  · Blog Redesign.dc.html — TERMINAL 발전안 + 인터랙션 프로토타입

■ 계승하는 것
  · 웜네이비 + 골드 팔레트 (대비 검증 후 일부 보정)
  · 터미널 은유, 픽셀 폰트, 모노 메타 정보
  · 글 목록 행의 호버 인터랙션 (좌측 골드 바 성장 → 제목 색 전환 → 화살표 슬라이드 인)
  · 상세 페이지의 읽기 지원 3종 (진행바 · 목차 자동 하이라이트 · 코드 복사)
  · 카테고리 컬러 3종 개념
  · 모션 이징 cubic-bezier(.2,.7,.3,1)

■ 구조가 바뀐 것 (가장 중요)
  · 홈 시안 3종 중 택1이 아닙니다.
    → 터미널 UI는 "전역 헤더(GNB)"로 승격되어 모든 페이지 공통이 됩니다.
    → 홈 히어로는 별개로, canvas/SVG 기반 "별자리" 그래픽으로 새로 만듭니다.
    → 즉 절제된 터미널 헤더 + 화려한 그래픽 히어로가 한 화면에 공존합니다.

■ 폐기된 것
  ✗ "● OPEN TO WORK" 상태 배지
  ✗ "$ resume --download" / "$ git clone works" 버튼
  ✗ 스킬 레벨 게이지 (React Lv.9 등)
  ✗ "▶ PRESS START", "QUEST LOG", "구독", "∞ 호기심"
  ✗ 터미널 창의 신호등 3개(빨강·노랑·초록)
      — 전 페이지 헤더에 창 컨트롤이 있으면 "창인가 사이트인가" 혼란을 주고,
        빨간 점은 닫기 버튼으로 오인됩니다
  ✗ 본문을 내부 스크롤 컨테이너(max-height + overflow-y)에 넣는 구조
      — 프로토타입 편의용이었습니다. 실제로는 페이지 전체가 스크롤됩니다

■ 새로 생긴 것
  · 라이트 모드 (양 테마 필수)
  · 한글 픽셀 폰트
  · 전역 터미널 헤더
  · 별자리 히어로
```

## 0. 적용 범위

**적용 대상 — UI 노출 텍스트**
버튼·링크·라벨·플레이스홀더·툴팁·빈 상태·에러·로딩·404·페이지 제목·메타 설명·`aria-label`·배지·페이지네이션·목차·공유 문구.

**적용 대상 아님 — 글 본문**
`public/_posts/*.md` 41개의 본문은 **필자의 글**입니다. 이 가이드는 글의 문체를 규제하지 않습니다.
단, 글에서 **UI로 새어나가는 값**(제목·태그·카테고리·요약)은 §6.11의 규격을 따릅니다.

**충돌 시 우선순위**
정확성 > 접근성 > 간결함 > 톤/재미. **재미가 이유가 되어 정확성을 깎지 않습니다.**

## 1. 보이스 — 누구의 목소리인가

### 1.1 한 문장 정의

> **자기 일을 오래 해온 사람이, 자기 작업실을 구경시켜 주는 목소리.**
> 과시하지 않고, 설명은 정확하고, 가끔 농담을 한다.

### 1.2 이 사이트가 처한 조건 (톤을 결정하는 사실)

| 조건 | 톤에 미치는 영향 |
|------|-----------------|
| **포트폴리오 ≥ 개인 아카이브 ≫ 트래픽** | 낯선 사람(채용 담당자 포함)이 **처음** 본다는 전제. 내부 농담·맥락 없는 축약 금지 |
| **재직 중이며 이직에 열려 있음. 단, 티 나지 않기를 원함** | 구직 상태를 **말로** 알리지 않음. 작업물이 대신 말하게 함 (§5) |
| **터미널·픽셀이라는 위트 있는 껍데기** | 재미는 **시각·장식**이 담당. 문장은 그 반대편에서 균형을 잡음 |
| **한국어 단일** | 영어 UI 라벨을 장식으로 섞지 않음 (§4.3) |
| **최신성 강조** | "지금도 하고 있다"는 인상. 과거형 자랑보다 현재형 활동 |

### 1.3 톤의 세 축

**① 정확 > 재치**
읽는 사람이 **무엇을 해야 하는지 즉시 알 수 있어야** 합니다. 재치는 그 다음입니다.

- ✅ `일치하는 글이 없어요` + `필터 초기화`
- ❌ `grep: no matches found` — 뜻은 통하지만 다음 행동을 알려주지 않음

**② 겸손한 자신감**
증거를 보여주고 평가는 읽는 사람에게 맡깁니다. 자기 등급화 금지.

- ✅ `최근에는 브라우저 내장 AI API를 다뤘어요`
- ❌ `React 숙련도 Lv.9` / `프론트엔드 전문가`

**③ 독자를 시험하지 않음**
이 사이트는 퍼즐이 아닙니다. 개발자만 아는 은유를 **유일한 정보 전달 수단**으로 쓰지 않습니다.

- ✅ 화면: `$ 이력서 보기` / 스크린리더·의미: `이력서 보기`
- ❌ `$ resume --download` — 파일 형식도, 무슨 일이 일어나는지도 모름

### 1.4 위트의 정지선 — 여기서 멈춘다

**농담해도 되는 곳**
프롬프트 기호(`$`, `➜`), 경로 표시(`~/posts`), 섹션 라벨, 히어로 문구, 404 제목, 워드마크, 잔디맵 캡션, 로딩 문구.

**농담하면 안 되는 곳 — 4개 정지선**

| # | 멈추는 지점 | 이유 |
|---|-------------|------|
| **S1** | **사용자가 뭔가를 잃거나 실패했을 때** — 에러, 글을 못 찾음, 네트워크 실패 | 실패한 사람 앞에서 농담하면 조롱으로 읽힘. 무엇이 잘못됐고 어떻게 회복하는지만 |
| **S2** | **행동을 지시하는 라벨** — 버튼, 링크, 폼 라벨 | 라벨이 애매하면 클릭이 도박이 됨. 라벨은 **결과를 예고**해야 함 |
| **S3** | **접근성 텍스트** — `aria-label`, `alt`, 스크린리더용 이름 | 장식 기호가 음성으로 읽히면 소음. §7 |
| **S4** | **사실을 전달하는 값** — 날짜, 개수, 읽기 시간, 카테고리 | 숫자와 사실은 꾸미지 않음 |

**판정 예시**

| 문구 | 위치 | 판정 |
|------|------|------|
| `➜ ~ whoami` | 히어로 장식 | ✅ 통과 — 장식이고, 아래 실제 이름이 있음 |
| `$ 최신 글 읽기` | 주 버튼 | ⚠️ 조건부 — `$`가 `aria-hidden`이고 라벨이 `최신 글 읽기`면 통과 |
| `grep: 일치하는 글이 없습니다.` | 빈 상태 | ❌ **S1 위반** — 실패 상황에 농담 + 회복 경로 없음 |
| `$ resume --download` | 보조 버튼 | ❌ **S2 위반** — 무엇이 다운로드되는지 불명 |
| `alt="🤖"` | 썸네일 | ❌ **S3 위반** |

## 2. 터미널체 사용 규칙

이 사이트의 정체성이자, **가장 오용되기 쉬운 부분**입니다.

### 2.1 대원칙 — 장식 레이어와 정보 레이어를 분리한다

터미널체는 **정보 위에 덧입히는 장식 레이어**입니다. 장식을 걷어내도 문장이 온전해야 합니다.

```
[장식 레이어]  $  ➜  ~  #  ●  ▸       ← aria-hidden, 색·서체로만 존재
[정보 레이어]  최신 글 읽기            ← 이것만으로 완결
```

**테스트: 장식을 다 지웠을 때 문장이 남는가?**

| 원문 | 장식 제거 후 | 판정 |
|------|-------------|------|
| `$ 최신 글 읽기` | `최신 글 읽기` | ✅ 남음 |
| `➜ ~ whoami` | `whoami` | ⚠️ 장식이 아니라 **내용이 영어 명령어** — 히어로 장식으로만 허용 |
| `grep: 일치하는 글이 없습니다.` | `일치하는 글이 없습니다.` | ✅ 남지만 §2.2 실패 |
| `$ resume --download` | `resume --download` | ❌ 한국어가 없음 |

### 2.2 3문항 테스트 — 터미널체를 써도 되는가

새 문구를 만들 때 **셋 다 YES여야** 터미널체를 씁니다.

> **Q1. 이 화면이 실패·에러·빈 상태인가?** → YES면 **쓰지 않는다** (S1)
> **Q2. 터미널을 한 번도 안 써본 사람이 이 문구만 보고 다음 행동을 아는가?** → NO면 **쓰지 않는다**
> **Q3. 명령어를 한국어로 바꿔도 재미가 남는가?** → NO면 그 재미는 **명령어 자체에만 있던 것** → 쓰지 않는다

**Q3 적용 예시**
- `$ 최신 글 읽기` → `최신 글 읽기` + `$` 장식. 재미는 `$`와 모노 서체에 있음 → **유지 ✅**
- `$ ls skills/` → `기술 목록`. 재미가 `ls`에만 있었음 → **`$ 기술 스택` 으로 교체**
- `grep: 일치하는 글이 없습니다.` → `일치하는 글이 없어요`. `grep:`이 없어도 손해 없음 → **`grep:` 제거**

### 2.3 위치별 허용 범위

| 위치 | 터미널체 | 규칙 |
|------|:---:|------|
| 워드마크 | ✅ | `Seobisback.log` |
| 경로 표시(브레드크럼) | ✅ | `~/posts/<slug>.md` — 실제 위치와 **일치해야 함**. 가짜 경로 금지 |
| 히어로 프롬프트 | ✅ | `➜ ~ whoami` 등 영어 명령어 허용. **장식이며, 바로 아래 한국어 실내용이 따라올 것** |
| 섹션 라벨 | ✅ | `$ 기술 스택`, `$ 연락처` — **명령어가 아니라 한국어 명사** |
| 주/보조 버튼 | ⚠️ | `$` 기호만 허용. 라벨은 한국어 (§6.1) |
| 검색 플레이스홀더 | ⚠️ | `제목, 태그로 검색` — `grep posts...` 금지 (§2.2 Q2 실패) |
| 목록 헤더 | ✅ | `➜ 최신순 · 41개` |
| 빈 상태 | ❌ | 평문만 |
| 에러 | ❌ | 평문만 |
| 로딩 | ⚠️ | 짧은 장식 1개까지 (`불러오는 중…` + 커서) |
| 404 제목 | ✅ | 유일한 예외 — §6.5 |
| 툴팁·`aria-label` | ❌ | 평문만 |
| 메타값(날짜·개수) | ❌ | 숫자와 단위만 |

### 2.4 명령어를 쓸 때의 정확성 규칙

터미널체를 쓴다면 **실제로 말이 되는 명령어**여야 합니다. 개발자가 보는 사이트에서 틀린 명령어는 위트가 아니라 흠입니다.

- ✅ `ls -lt ~/posts` — 시간순 정렬. 실제로 최신순 목록에 붙어 있으면 정확
- ✅ `cd ..` — 상위로. 브레드크럼의 "뒤로"에 정확
- ❌ `git clone works` — `git clone`은 URL을 받음. 페이지 이동에 붙이면 틀린 은유
- ❌ `grep: 일치하는 글이 없습니다.` — `grep`은 한국어 에러를 내지 않음

**필터·정렬 상태를 명령어로 에코할 때**는 실제 상태와 동기화되어야 합니다.
`➜ ls -lt ~/posts --category=study` ← 실제로 study 필터가 걸려 있을 때만.

## 3. 한국어 표기 규칙

### 3.1 높임 — 두 층위로 나눈다

| 층위 | 문체 | 대상 | 예 |
|------|------|------|-----|
| **UI 마이크로카피** | **해요체** | 버튼·에러·빈 상태·툴팁·안내·로딩·404 | `일치하는 글이 없어요`, `주소를 다시 확인해 주세요` |
| **서술형 소개문** | **합쇼체** | About·프로필 소개·푸터 설명·글 요약 | `더 나은 서비스를 만드는 방법을 고민합니다` |

**구분 기준 (외우기 쉬운 규칙)**

> **누르면 사라지는 텍스트 → 해요체.**
> **읽히려고 존재하는 문장 → 합쇼체.**

근거: 마이크로카피의 해요체는 부드럽고 덜 사무적이며, 자기소개의 합쇼체는 신뢰감을 만듭니다. 현재 코드에도 이미 두 문체가 섞여 있으므로(`정리해요.` / `좋아합니다.`) 혼용을 **없애는 대신 규칙화**합니다.

**금지**: 평어체(`없다`, `확인해라`), 과도한 축약(`글없음`), 명사종결 남용(`검색 불가`).

### 3.2 문장부호

| 부호 | 규칙 |
|------|------|
| 마침표 `.` | **완결된 문장에만.** 버튼·라벨·제목·메뉴에는 **찍지 않음** |
| 느낌표 `!` | **한 화면에 0개를 기본으로.** 과장은 신뢰를 깎음. `Hello World!` 같은 관용구만 예외 |
| 물음표 `?` | 사용자에게 **실제로 물을 때만**. 수사의문문 금지 |
| 말줄임표 | `…` (U+2026). `...` 금지 |
| 가운뎃점 `·` | 메타 정보 구분자. 앞뒤 공백 1칸 — `Survey · 2025.05.26 · 6분` |
| 물결 `~` | **터미널 경로에서만.** 범위에는 `–`(엔 대시) |
| 따옴표 | 한글은 `'`·`"`(곧은 따옴표) 통일 |
| 쉼표 | 나열이 3개 이상일 때만. 2개는 `와/과` |
| 슬래시 `/` | 앞뒤 공백 없음 — `프론트엔드/백엔드` |

### 3.3 영문·기술 용어

**원칙: 기술 고유명사는 원어 그대로, 일반 개념은 한국어.**

| 구분 | 표기 | 예 |
|------|------|-----|
| 제품·기술 고유명 | **원어, 공식 대소문자** | `React`, `TypeScript`, `Next.js`, `GitHub`, `Vite`, `Zustand`, `JavaScript`, `macOS`, `Node.js` |
| 일반화된 개념 | **한국어** | 터미널, 카테고리, 태그, 목차, 검색, 다크 모드 |
| 한글 병기 | **하지 않음** | ❌ `React(리액트)` |
| 한글 음차 | **하지 않음** | ❌ `리액트`, `타입스크립트` |
| 조사 결합 | 원어 발음 기준 | `React를`, `TypeScript로`, `GitHub에서` |

**자주 틀리는 표기 (고정 목록)**
`JavaScript`(자바스크립트 X, Javascript X) · `TypeScript` · `Next.js`(NextJS X) · `Node.js` · `GitHub`(Github X) · `macOS` · `iOS` · `npm`(소문자) · `CSS Modules` · `Vite` · `MongoDB` · `WebXR`

**영어 UI 라벨 금지**
`Search` → `검색` / `More` → `더 보기` / `Home` → `홈` / `Read more` → `이어서 읽기`
이유: 한국어 사이트에서 영어 라벨은 정보가 아니라 장식입니다. 장식은 §2의 장식 레이어가 이미 담당합니다.
**예외**: 워드마크(`Seobisback.log`), 카테고리 원본값이 영어인 경우(§6.11), 코드·경로 문자열.

| 항목 | 형식 | 예 | 비고 |

### 3.6 이모지

- **장식으로 한 화면에 최대 1개.** 라벨·버튼·에러에는 **금지**
- 이모지가 **유일한 정보 전달 수단이 되면 안 됨** (§7.1)
- 현재 코드의 `😅 Oops! This Page is under construction.` — **폐기** (§8 판정표)
- 예외: 글 썸네일 이모지는 **장식**이며 `aria-hidden` (§7.1)

기술명 옆에 숫자만 놓으면(`Python 16` `React 14`) 읽는 사람은 그것이 **숙련도인지 연차인지 빈도인지 알 수 없습니다.** 숫자 자체는 사실이어도, 맥락이 없으면 §5.3이 금지하는 자기 신고 등급으로 읽힙니다.

| 상황 | 제목 | 설명 | 액션 |
|------|------|------|------|
| 검색 결과 0 | `일치하는 글이 없어요` | `다른 키워드로 찾아보거나, 전체 글을 둘러보세요.` | `검색어 지우기` / `전체 글 보기` |
| 필터 결과 0 | `이 조건에 맞는 글이 없어요` | `카테고리나 태그를 바꿔보세요.` | `필터 초기화` |
| 태그 결과 0 | `이 태그의 글이 아직 없어요` | — | `전체 태그 보기` |
| Works 미완 | `아직 정리 중이에요` | `작업물은 곧 여기에 올라옵니다.` | `GitHub에서 보기 ↗` |

- ❌ `grep: 일치하는 글이 없습니다.` — S1 위반 + 액션 없음
- ❌ `Oops! Sorry, no posts found.` — 영어 + 사과 과잉 + 액션 없음
- **사과하지 않음.** `죄송합니다`는 사용자 잘못이 아닌 상황에서 감정 부담만 줍니다

### 6.3 에러

**필수 3요소**: ① 무엇이 실패했는지 ② 사용자 잘못이 아님(암시) ③ **재시도 또는 우회 경로**

| 상황 | 제목 | 설명 | 액션 |
|------|------|------|------|
| 글 로딩 실패 | `글을 불러오지 못했어요` | `잠시 후 다시 시도해 주세요.` | `다시 시도` / `글 목록으로` |
| 목록 로딩 실패 | `목록을 불러오지 못했어요` | `네트워크 상태를 확인해 주세요.` | `다시 시도` |
| 글 없음(잘못된 id) | `찾는 글이 없어요` | `주소가 바뀌었거나 삭제된 글일 수 있어요.` | `글 목록 보기` / `검색하기` |
| **앱 전체 크래시** (ErrorBoundary) | `화면을 표시하지 못했어요` | `새로고침하면 대부분 해결돼요. 그래도 안 되면 잠시 뒤에 다시 들러 주세요.` | `새로고침` / `홈으로` |

**앱 크래시 문구가 특별한 이유** — 이건 **앱이 죽었을 때 사용자가 보는 마지막 화면**입니다. 두 가지를 특히 지킵니다.

1. **`잠시 후 다시 시도해 주세요`를 쓰지 않습니다.** 그 문장은 *시간이 지나면 낫는 문제*를 뜻하는데, ErrorBoundary가 잡는 것은 대개 **코드 결함**이라 기다려도 그대로입니다. 사용자에게 거짓말이 됩니다. **React 렌더 크래시는 전체 새로고침이 상태를 지워 실제로 해결되는 경우가 많으므로**, 그 사실을 그대로 말합니다.
2. **액션은 `다시 시도`가 아니라 `새로고침`.** `다시 시도`(리렌더)는 같은 결함을 다시 밟아 대개 또 실패합니다. **실제로 통하는 수단을 이름으로 부릅니다.**

> 위트 금지가 가장 강하게 적용되는 자리입니다 (§1.4 S1). 터미널 농담·이모지·느낌표 전부 금지.

**금지**
- 기술 용어 노출 — ❌ `Failed to fetch post`, `500 Internal Server Error`, `TypeError: …`
- 터미널 농담 — ❌ `segmentation fault (core dumped)`
- 원인 없는 통보 — ❌ `에러 발생: {message}` (현재 코드)
- 사용자 탓 — ❌ `잘못된 요청입니다`

### 6.4 로딩

- 기본: `불러오는 중…` (커서 blink는 **장식**, `aria-hidden`)
- **스켈레톤이 있으면 텍스트 불필요**
- 3초 이상 예상 시에만 진행 표시. 그 외에는 문구 바꾸지 않음(연속 교체는 산만)
- ❌ `로딩 중...` (말줄임표 표기), ❌ `Loading...`, ❌ `잠시만 기다려주세요!`

### 6.5 404 페이지 — 유일한 위트 허용 예외

**왜 예외인가**: 404는 사용자가 **아무것도 잃지 않은** 실패입니다(S1 미해당). 오히려 브랜드를 보여줄 몇 안 되는 자리입니다. 단, **위트는 제목 1줄까지**이고 나머지는 평문 + 회복 경로.

**구조 (Claude Design 전달용 규격)**

```
[대형 픽셀 그래픽 — 404]
제목      이 경로에는 아무것도 없어요            (≤20자, 위트 허용)
설명      주소가 바뀌었거나, 처음부터 없던 페이지예요.   (≤45자, 평문)
액션      [홈으로]  [글 목록으로]                 (2개 이상 필수, 형식 통일 §6.1-1)
보조      [검색으로 찾기]                        (선택)
장식      ▸ ~ cd <잘못된경로>                    (aria-hidden, 실제 경로 표시)
```

- 헤더의 경로 슬롯은 **`~`로 고정**하고, 잘못된 경로는 **이 장식 라인이 단독으로** 담당합니다. `cd`가 실패하면 사용자는 원래 있던 곳에 그대로 있으므로 은유상으로도 맞습니다 (handoff-step1-shell §6-1c)

- ✅ 허용: `이 경로에는 아무것도 없어요`, `길을 잘못 드셨어요`
- ❌ 금지: `404 NOT FOUND`(만), `segmentation fault`, `당신은 길을 잃었습니다`(겁줌), 자책 유도
- **실제 잘못된 경로를 장식 라인에 표시**하면 디버깅에도 유용하고 위트도 정확해짐

### 6.6 툴팁

- 1행, 25자 이내
- **버튼 라벨을 반복하지 않음.** 추가 정보만
- 툴팁에만 있는 정보 금지 (터치·키보드에서 접근 불가)
- 잔디맵: **`2025.05.26 · 활동 많음`**
  ⚠️ ~~`2025.05.26 · 4회`~~ — 데이터 계약상 셀 값은 **레벨 0~4이지 기여 횟수가 아닙니다.** 횟수로 표기하면 **거짓 정보**입니다.
  레벨 → 말 표현 5단계: `활동 없음` / `조금` / `보통` / `많음` / `아주 많음`
  → 이 표현이 **색 외의 전달 채널**을 만들어 §7.5(색만으로 전달 금지)를 충족합니다. 집계 수치는 요약 라인(`최근 1년 N회 · 마지막 활동 <날짜>`)과 격자의 `aria-label`이 담당하므로, 셀 단위 횟수가 없어도 정보 손실은 없습니다.
  → 횟수를 정말 노출하려면 **데이터 계약에 `count`를 추가**해야 합니다. 레벨에서 역산하지 마세요.

### 6.7 메타 정보 (날짜·읽기 시간·카테고리)

**형식**: `카테고리 · 날짜 · 읽기 시간`
**예**: `Survey · 2025.05.26 · 6분`

- 저자는 **표시하지 않음** — 41개 글 모두 동일 저자라 정보량이 0 (그 자리에 읽기 시간을 넣음)
- 구분자 `·` 앞뒤 공백 1칸
- 순서 고정. 화면마다 순서를 바꾸지 않음

### 6.8 태그

- **글에 적힌 원문 그대로.** 임의 번역·대소문자 변경 금지
- 표시 시 `#` 접두 (장식, `aria-hidden`)
- **최대 3개 노출 + `+N`** (실제 데이터에 글당 최대 15개)
- `+N`의 접근가능한 이름: `태그 5개 더 보기`
- 태그 페이지 제목: `#React 글 12개`

### 6.9 페이지네이션

- 형식: `3 / 7` (현재 / 전체)

- 기호 `<<`, `<`, `>`, `>>`는 **장식** — aria-label 필수
- 터미널 장식 허용: `➜ page 3 / 7`

### 6.10 목차 (TOC)

- 라벨: `목차` (`INDEX`, `Contents` ❌)
- 항목은 **본문 heading 원문 그대로.** 요약·변형 금지
- 모바일 접힘 상태 라벨: `목차` + `aria-expanded`

### 6.11 글에서 UI로 새어나가는 값

| 값 | 규격 |
|----|------|
| 제목 | 원문 그대로. 실제 16~96자. **UI가 96자를 견뎌야 함**(2행 클램프) |
| 카테고리 | 원본값 `Survey`/`Study`/`Activity` — **표시는 원본 대소문자 유지**. 한국어 병기하지 않음(3개뿐이고 의미가 자명) |
| 태그 | §6.8 |
| 요약 | 본문 첫 문단에서 자동 추출. **문장 중간에서 자르지 않고** 문장 경계 + `…` |
| 읽기 시간 | 자동 계산, `N분` |

### 6.12 공유

- 버튼 라벨: `링크 복사` → 완료 시 `복사됨`
- 완료 알림은 `aria-live="polite"`, 1.4초 후 원복
- 공유 문구를 자동 생성하지 않음 (제목 + URL만)

| 태그 인덱스 | `태그 · Seobisback.log` | `이 블로그가 다루는 주제 27개.` |

#### 6.13a. `index.html`의 메타 3종 — 같은 값을 씁니다

`description` · `og:description` · `twitter:description` **세 곳 모두 위 홈 설명문을 그대로** 넣습니다. 검색 결과와 공유 카드에 같은 문장이 나가야 인상이 갈리지 않습니다.

```
프론트엔드 개발자 김섭우의 기술 블로그입니다. 공부하거나 조사한 내용을 기록합니다. 프론트엔드, 브라우저, 그리고 그 사이의 이야기를 남깁니다.
```

| 항목 | 값 |
|---|---|
| 길이 | **80자** — 권장 80~110 하단, 상한 120 이내 |
| 문체 | **합쇼체** — 읽히려고 존재하는 문장 (§3.1) |
| 구 문구 | ~~`공부하는 기술, 경험에 대한 이야기를 정리해요.`~~ — 해요체이고(§8-36 판정), **누가 쓴 블로그인지가 없습니다** |

**왜 첫 문장에 "프론트엔드 개발자 김섭우"를 넣는가**
이 자리는 **검색 결과와 공유 카드**입니다. 목적 1순위가 포트폴리오이고 findability의 기준이 "내 이름으로 검색했을 때 나오는가"(product.md §9-1)인데, 구 문구에는 **이름도 직군도 없어** 그 목적을 전혀 돕지 못했습니다. 링크를 받은 사람이 카드만 보고 "누구의 무엇인지"를 알 수 있어야 합니다.

**왜 구직 신호가 아닌가**
직군과 이름은 **사실 서술**입니다. §5.2가 금지하는 것은 `OPEN TO WORK`·`채용 문의` 같은 **요청**이지 자기 소개가 아닙니다. 오히려 §5.1("상태를 말하지 말고 작업을 보여준다")에 정확히 부합합니다.

> 글 상세 페이지의 `og:description`은 이 값이 아니라 **각 글의 요약**입니다(§6.11). 빌드타임 프리렌더가 slug별로 주입합니다.

## 7. 접근성 라이팅

### 7.1 이미지·이모지 대체 텍스트

| 대상 | 규칙 | 예 |
|------|------|-----|
| **이모지 썸네일** | `aria-hidden="true"`. **대체 텍스트를 만들지 않음** | 옆에 글 제목이 이미 있어 중복 낭독이 됨 |
| **그라데이션 썸네일** | 장식 — `role="presentation"`, `alt=""` | |
| **프로필 사진** | 사람을 설명 | `alt="김섭우 프로필 사진"` (❌ `alt="github profile"`) |
| **본문 이미지** | 마크다운 `alt` 사용. **이미지가 전달하는 정보**를 서술 | ✅ `alt="Translator API 호출 순서도"` / ❌ `alt="이미지"`, `alt="스크린샷"` |
| **장식 글리프** `$ ➜ ● ▸ →` | `aria-hidden="true"` | |
| **로고·워드마크** | `alt="Seobisback.log 홈"` (링크일 때) | |

**`alt` 작성 3원칙**
1. `이미지`, `사진`, `그림`으로 시작하지 않음 (스크린리더가 이미 알림)
2. 장식이면 빈 `alt=""` — **빈 alt를 두려워하지 않음**
3. 본문에 이미 같은 설명이 있으면 `alt=""`

### 7.2 링크 텍스트

- **링크 텍스트만 떼어놓고도 목적지를 알 수 있어야** 함 (스크린리더의 링크 목록 탐색)
- ❌ `여기`, `더보기`, `클릭`, `자세히`, `→`
- ✅ `글 목록 더 보기`, `GitHub 프로필 보기`, `이 글 이어서 읽기`
- 같은 화면에서 **같은 텍스트가 다른 곳으로 가면 안 됨**
- 외부 링크는 `↗` + `aria-label`에 `(새 창)` 명시

### 7.3 `aria-label` 문구 규칙

1. **화면에 보이는 텍스트로 시작** — 음성 제어 사용자가 "OO 클릭"으로 조작 가능해야 함
2. **장식 기호 제외** — `$`, `➜`, `#` 제거
3. **역할 단어 넣지 않음** — `버튼`, `링크`는 스크린리더가 이미 읽음 (❌ `검색 버튼` → ✅ `검색 열기`)
4. **동작을 결과로 표현**

| 요소 | `aria-label` |
|------|-------------|
| 검색 아이콘 | `검색 열기` |
| 메뉴 햄버거 | `메뉴 열기` / `메뉴 닫기` (`aria-expanded` 병행) |
| 테마 토글 | `다크 모드로 전환` / `라이트 모드로 전환` |
| 맨 위로 | `맨 위로 이동` |
| 코드 복사 | `코드 복사` |
| 잔디맵 컨테이너 | `최근 1년 기여 활동 요약` (개별 칸은 `aria-hidden`) |
| 카테고리 필터 칩 | `Study 카테고리로 거르기, 글 30개` |
| 글 목록 행 링크 | `<글 제목>` (메타는 별도로 읽히게 두거나 생략) |

### 7.3a 랜드마크 이름 (`<nav>` · `<section>`의 `aria-label`)

§7.3은 **컨트롤**(버튼·링크) 규칙입니다. 랜드마크 영역 이름은 성격이 달라 별도로 정합니다.

1. **그 영역이 무엇인지 명사구로.** 동사·문장 형태로 쓰지 않습니다
2. **4~10자.** 스크린리더가 "…, 탐색"처럼 역할을 덧붙여 읽으므로 짧아야 합니다
3. **역할 단어를 넣지 않습니다** — `탐색`·`영역`·`메뉴`는 이미 읽힙니다
4. **같은 종류의 랜드마크가 한 화면에 둘 이상일 때만** 이름을 붙입니다. 하나뿐이면 생략

| ❌ | ✅ | 이유 |
|---|---|---|
| `여기서 갈 수 있는 곳` | **`돌아가기`** | 11자 → 4자. 문장이 아니라 명사구 |
| `탐색 메뉴` | `주요 메뉴` | 역할 단어 중복 |
| `푸터 영역` | `사이트 정보` | 역할 단어 중복 |

> §7.2가 금지하는 `여기`는 **링크 텍스트**에 대한 규칙이라 랜드마크 이름에는 직접 적용되지 않습니다. 다만 위 1~3을 지키면 `여기`가 들어갈 자리가 애초에 없습니다.
> 404의 복구 링크 묶음은 전역 헤더 내비와 구분해야 하므로 이름이 필요합니다 → `<nav aria-label="돌아가기">`

### 7.4 상태 변화 알림

- `복사됨`, `필터 적용됨` 등은 `aria-live="polite"`
- **`aria-live`에 장식 기호를 넣지 않음** — ❌ `✓ 복사됨` → ✅ `복사됨`
- 페이지 전환 시 `<title>` 갱신 (SPA 필수)

### 7.5 색에 의존하지 않기

- 카테고리는 **색 점 + 텍스트 라벨** 항상 병기
- `NEW` 배지는 **텍스트**로 (색만 다른 점 ❌)
- 잔디 단계는 툴팁/`aria-label`에 **수치**를 담음
- 에러는 빨간색 + **아이콘 또는 "오류" 단어**

## 10. 체크리스트 (배포 전)

**정확성**
- [ ] 모든 버튼 라벨이 **누른 뒤 결과를 예고**하는가
- [ ] 없는 기능의 버튼·링크가 없는가 (`구독`, `alert()` 스텁)
- [ ] 명령어 은유가 실제로 말이 되는가 (§2.4)
- [ ] 필터·정렬 에코가 실제 상태와 일치하는가

**톤**
- [ ] UI 마이크로카피가 해요체, 서술문이 합쇼체인가 (§3.1)
- [ ] 실패·에러·빈 상태에 농담이 없는가 (S1)
- [ ] 한 화면에 느낌표 0~1개, 이모지 0~1개인가
- [ ] 영어 UI 라벨이 없는가 (워드마크·코드·경로 제외)

**구직 신호**
- [ ] `OPEN TO WORK`류 표현이 없는가
- [ ] 자기 신고 등급(`Lv.9`, `%`, `★`)이 없는가
- [ ] 이력서가 주 CTA 자리에 없는가
- [ ] 연락처는 명확히 접근 가능한가

**접근성**
- [ ] 장식 기호(`$ ➜ ● ▸`)가 전부 `aria-hidden`인가
- [ ] 링크 텍스트만으로 목적지를 알 수 있는가
- [ ] 아이콘 버튼에 `aria-label`이 있고, **보이는 텍스트로 시작**하는가
- [ ] 이모지 썸네일이 `aria-hidden`인가
- [ ] 색만으로 전달되는 정보가 없는가
- [ ] 페이지 전환 시 `<title>`이 갱신되는가

**형식**
- [ ] 날짜 `2025.05.26`, 읽기 시간 `6분`, 개수 `41개`
- [ ] 기술 고유명사 대소문자가 §3.3 목록과 일치하는가
- [ ] 말줄임표가 `…`인가
- [ ] 길이 상한(§4)을 넘는 문구가 없는가

## 1. 주 과업

> **처음 보는 사람이 "이 사람이 무엇을 만들어 왔는지"를 스크롤 한 번으로 파악하고, 궁금한 항목이 있으면 그 하나를 깊게 읽는다.**

이 화면의 조건은 다른 어떤 화면과도 다릅니다.

| 조건 | 결과 |
|---|---|
| 고객사 화면 캡처 사용 불가 | **썸네일 0장.** 이미지가 위계를 만들 수 없음 |
| 고객사·프로젝트명 전부 익명화 | 제목이 브랜드 후광을 못 씀. 제목이 **기능 설명문**이 됨 |

| 성과 % 수치 전부 제외 | "얼마나 잘했나"를 말할 수 없음 |
| 초기 상세 0건 가능 | 목록이 **끝**일 수 있음 |

남는 판단 재료는 **제목 · 기간 · 역할 · 요약 1문장 · 기술 스택** 다섯 개뿐입니다.
그래서 이 화면은 이미지가 아니라 **정보의 구조**로 버팁니다 — 시안 서문의 이 진단은 정확하고, 이 문서는 그 전제를 그대로 계승합니다.

**판정 테스트** (product.md §13-4): 현재 직장 동료가 이 페이지를 봤을 때 "이직 준비"로 읽히면 실패입니다. 이 문서의 모든 카피 판정은 이 기준을 통과합니다.

## 2. 판단 노트 5건 판정

### 2-1. 「구조는 (b)+(c) — 연도 축 + 행 스트림」 → ✅ **채택**

시안이 (a) 카드 그리드를 **실제로 그려서** 2022년 1건 그룹에 빈 칸 두 개가 남는 상태를 보여준 것은 근거 제시 방식으로 옳습니다. 3열 그리드에서 각 연도의 나머지는 `2025:0 / 2024:2 / 2023:0 / 2022:2` — 두 그룹에서 빈 칸이 발생하고, 1건 그룹을 전폭으로 늘리면 그 항목만 특별해집니다. 어느 쪽도 §3의 원칙을 만족하지 못합니다.

행 스트림은 **항목 수가 리듬을 바꾸지 않는** 유일한 구조입니다. 채택합니다.

> **단 결함 1건**: 연도 축의 `position: sticky; top: 16px`은 전역 헤더(48px sticky) 아래로 파고듭니다. §5-2에서 수정합니다.

### 2-2. 「스택 칩 5개 + `+N`, 칩 줄 1행 고정」 → 🟡 **수정 채택**

- **개수 5/3 채택.** ~~실측 분포 `3:2건 4:2 5:1 6:1 7:6 8:1 10:1 13:1`~~ **→ 🔴 정정 (2026-08-13).** 이전 판은 최소값을 3개로 적어 **사이드 3건에도 스택이 있다고 가정**했습니다. `works-data.json` 재실측 정본:

  ```
  스택 개수 오름차순  0 0 0 4 5 6 7 7 7 7 7 7 8 10 13
  분포              0:3건  4:1  5:1  6:1  7:6  8:1  10:1  13:1
  ```

  **0개 3건은 사이드 프로젝트 3건**(`pet-healthcare-wearable` · `restaurant-archive-platform` · `certification-exam-service`)이며, 원본 경력기술서에 사용 기술이 적혀 있지 않은 항목입니다.

  **5개 채택 결론은 이 정정에 영향받지 않습니다** — 5개 초과가 여전히 **10/15건**이고, 6개로 올려도 **9/15**로 거의 안 줄며, 3개로 줄이면 "무엇으로 만들었나"가 사라집니다. 5개가 맞습니다
  🔴 **다만 0개 케이스의 렌더 규칙이 이 문서에 없었습니다** → §5-4에 신설
- **접힘 상태 1행 고정(24px) 채택.** 4개짜리와 13개짜리가 같은 행 높이를 갖는다는 판단은 옳습니다 (스택이 있는 항목의 최소는 3개가 아니라 **4개**입니다)
- 🔴 **펼침이 동작하지 않습니다.** 시안은 칩 컨테이너가 `height:24px; overflow:hidden`이라 `+N`을 눌러 배열을 전부 넘겨도 **화면에 아무 변화가 없습니다.** 실측: 13개 칩의 총 폭 ≈ **1,047px** > 데스크톱 행 콘텐츠 폭 **844px** → 펼치면 반드시 2행이 됩니다. §5-4에서 수정

### 2-3. 「글과 같은 언어, 다른 배열 규칙」 → 🟡 **수정 채택**

- **조형 분리 채택**: 글 = 자유 좌표 성좌 / 작업 = 격자 정렬 + 직각 배선. "같은 집안, 다른 종류"라는 판단은 정확하고, 사용자가 글 목록 썸네일을 41편 전량 생성 그래픽으로 확정한 상태에서 두 화면이 어긋나지 않게 하는 유일한 방법입니다
- 🔴 **색을 유형에서 뽑는 규칙은 반려**. 시안은 `개인·팀 → t.sAcc`(라일락)를 씁니다. 그런데 `--color-status-accent`는 값이 `--color-cat-study`와 **동일**합니다 — 글 목록에서 라일락 타일은 `Study` 카테고리를 뜻합니다. 같은 색이 두 화면에서 다른 것을 의미하게 됩니다. 게다가 유형은 이미 **텍스트 배지**가 말하고 있어 색은 정보를 더하지 않습니다
  → **작업 타일은 `--color-accent-text` 단일.** 색이 두 화면을 가르는 축이 되고(카테고리색 = 글 / 골드 = 작업), 조형이 두 번째 축이 됩니다
- 🔴 **시드를 `title` → `slug`로 변경.** 익명 표기안은 아직 문구가 조정될 수 있고, 제목이 한 글자만 바뀌어도 그림이 통째로 달라집니다. `slug`는 URL이라 불변 계약입니다. 글 목록도 같은 규칙이어야 합니다
- 🔴 **DOM 노드 수 반려.** 시안 방식은 행당 `격자 9 + 배선 2(n−1) + 노드 n` = 스택 13개면 **46노드**, 15행이면 **690노드**. STEP 4 §6-3 R7이 요구한 **인라인 SVG 1노드**로 교체

### 2-4. 「15건 전부 생성 그래픽」 → ✅ **채택** (모바일 예외 추가)

### 4-1. 기술 결정 — `aria-disabled` 반려

| 방식 | 판정 |
|---|---|
| `<a aria-disabled="true">` | 🔴 **반려.** 링크가 포커스는 받으면서 아무 데도 가지 않습니다. 키보드 사용자가 15번 탭해서 15번 아무 일도 안 일어나는 경험이 됩니다. `aria-disabled`는 폼 컨트롤용이고 링크에는 네이티브 대응이 없습니다 |
| `<a href>` 없이 `<a>` | 🔴 **반려.** `href` 없는 `<a>`는 링크 역할을 갖지 않지만 스타일이 링크로 남아 혼선 |
| **`<a>`를 렌더하지 않음** | ✅ **채택.** 제목이 `<h3>` 평문. 포커스 불가, 커서 `default`, 접근성 트리에 링크가 없음 |

**커서**: 행 전체 `cursor: default`. 상세 있는 행만 stretched link 영역이 `cursor: pointer`.
**포커스 순서**: 상세 있는 행의 제목 링크 → (관련 글 링크) → (외부 링크). 상세 없는 행은 **탭 순서에서 완전히 빠집니다.**

#### 5-4a. 🔴 스택 0개 — 줄 자체를 렌더하지 않습니다 (2026-08-13 신설)

**실데이터 15건 중 3건이 스택 0개입니다** — 사이드 프로젝트 3건이며, 원본 경력기술서에 사용 기술이 없는 항목입니다(분포 정정은 §2-2). **이전 판은 분포의 최소값을 3개로 적어 이 케이스가 존재하지 않는 것처럼 기술했고, 그래서 렌더 규칙이 한 줄도 없었습니다.**

| 조건 | 렌더 |
|---|---|
| `stack.length === 0` | **칩 줄 컨테이너를 통째로 렌더하지 않습니다.** `+N` 버튼도 없습니다 |

## 8. `prefers-reduced-motion`

> 🔴 시안에 `@media (prefers-reduced-motion)`이 **0회** 등장합니다. 수동 미리보기 토글(`rm` 상태)이 모든 모션에 실제로 배선되어 있어 **설계는 있고 트리거만 없습니다.** STEP 2·3·4에 이어 **네 번째 반복**입니다.

### 8-1. 이 화면의 모션 전수

| # | 모션 | 기본 | `reduce` |
|:--:|---|---|---|
| 1 | 필터 전환 후 목록 재진입 `fadeUp` | `translateY(6px)` + opacity, `--dur-base` | **제거.** 즉시 최종 상태 |
| 2 | 필터 전환 시 목록 상단 스크롤 (§3-2) | `smooth` | **`auto`** (즉시 점프) |
| 3 | 행 호버 배경·제목 색 전환 | `--dur-base` `--ease-out` | **유지** (§8-3) |
| 4 | 행 호버 `→` 색 전환 | `--dur-base` | **유지** (색만, transform 없음) |
| 5 | 필터 칩 배경·테두리 전환 | `--dur-base` | **유지** |
| 6 | 스택 `+N` 펼침 높이 변화 | `--dur-slow` | **트랜지션 제거.** 즉시 최종 높이 |

### 8-2. 🔴 스켈레톤 — 시안 버그 재발

```
시안:  background-size: 640px 100%
       @keyframes shimmer { -320px → 320px }
```

**이동폭(640px)과 그라데이션 폭이 어긋납니다.** STEP 4 §9-2가 같은 버그(520 vs 320)를 지적했는데 값만 바뀐 채 반복됐습니다. **320px로 통일**하십시오.

```css
@media (prefers-reduced-motion: reduce) {
  .skeleton {
    animation: none;
    background: var(--color-skeleton-base);   /* 그라데이션을 통째로 교체 */
    background-size: auto;
  }
}
```

`animation: none`만 주면 sheen이 임의 위치에서 얼어붙어 막대마다 밝은 띠가 남습니다.

### 8-3. 색·투명도 전환을 유지하는 이유

`prefers-reduced-motion`은 전정 자극(위치·크기·회전)을 겨냥합니다(WCAG 2.3.3). 색 전환 160ms는 해당하지 않으며, 제거하면 호버 피드백이 끊겨 오히려 상태 파악이 어려워집니다.

**금지**: `*, *::before, *::after { transition: none !important }` 카펫 폭격. 모션별로 개별 처리하십시오.

### 8-4. 모션이 사라진 자리

필터 전환의 재진입 애니메이션은 "목록이 바뀌었다"는 유일한 시각 신호입니다. 저감 모드에서는 사라지고, 스크린리더 사용자는 애초에 받은 적이 없습니다.

→ §5-6의 목록 헤더 줄이 `aria-live="polite" aria-atomic="true"`로 이를 대신합니다. `➜`는 그 안에서 `aria-hidden` (WRITING_GUIDE §7.4).

## 9. 생성 그래픽 계약

### 9-1. 두 화면 한 컴포넌트

사용자가 **글 목록 썸네일을 41편 전량 생성 그래픽으로 확정**했으므로 두 화면 합계 **56개 타일**이 같은 시스템 안에 있어야 합니다.

```
<GeneratedTile variant="post" | "work" seed={slug} nodes={n} tone={…} width={96} height={64} />
```

| | `variant="post"` (글 41편) | `variant="work"` (작업 15건) |
|---|---|---|
| 조형 | 자유 좌표 성좌 — 점 + 직선 연결 | **격자 정렬 + 직각 배선(맨해튼 라우팅)** |
| 격자 | 없음 | 6열 × 3행, 배경에 옅은 격자선 |
| 시드 | **`slug`** | **`slug`** |
| 노드 수 | 태그 수 → `clamp(3, n, 9)` | 스택 수 → `clamp(3, n, 9)` |
| 노드 색 | `--color-cat-*` (카테고리) | **`--color-accent-text` 단일** |
| 배선 색 | `--color-constellation-link-strong` | 동일 |
| 배경 | 타일 배경 토큰 (§11-3 미정) | 동일 |
| 애니메이션 | 없음 | 없음 |

**나란히 놓았을 때 읽히는 것**: 같은 점·선·같은 토큰 → 한 시스템. 자유 배치 vs 격자 정렬, 카테고리색 vs 골드 → 다른 종류. 시안 노트 3의 의도를 그대로 구현합니다.

### 9-2. 결정론 규칙

```
seed = FNV-1a(slug)                          ← title 아님. slug는 URL이라 불변
n    = clamp(3, stack.length, 9)             ← 시안은 상한 18(=6×3). 13개를 다 찍으면
                                                96×64에서 격자가 꽉 차 형태가 사라집니다
격자  = 6열 × 3행 → cw = W/7, ch = H/4       (96×64 → cw 13.7px, ch 16px)
셀 선택 = LCG(seed) 로 18칸 중 n칸을 비복원 추출
정렬  = 열 오름차순, 같은 열이면 행 오름차순   ← 배선이 좌→우로 흐르게
배선  = 인접 두 점을 수평 → 수직 2구간 직각 연결
```

| 요구 (STEP 4 §6-3) | 준수 |
|---|---|
| R1 결정론적 | ✅ `slug` 시드 + LCG. `Math.random` 없음 |
| R2 입력은 데이터에서만 | ✅ `slug` + `stack.length` |
| R3 색은 토큰에서 파생 | ✅ 단 `--color-cat-*`가 아니라 `--color-accent-text` (§2-3 근거) |
| R4 96×64 판독 가능 · 최소 3px | 🟡 **노드 4.8px ✅ / 배선 1.5px → `2px`로 상향** |
| R5 라이트 연결선 대비 | §9-3 |
| R6 `aria-hidden` + `role="presentation"` + `alt=""` | ✅ 시안 준수 |
| R7 인라인 SVG 1노드 | 🔴 **시안 반려** — span 46개/행 × 15행 = 690노드. SVG 1노드로 교체 |
| R8 애니메이션 없음 | ✅ |
| R9 고정 aspect box | ✅ CLS 0 |

**SVG 골격**

```svg

```

### 13-1. 🔴 `org` 표기 — 사용자 결정 필요

확정 사실은 **"과거 3사는 실명 / 현재 재직처 미표기 + 종료월 비움"** 입니다. 그런데 목록이 **연도 내림차순**이라 항목별 `org` 표기는 다음을 노출합니다.

```
2024.03  (과거사 A)     ← 표기
2024.02  (과거사 A)     ← 표기
…
2024.07  (비움)         ← 미표기
2024.06  (비움)         ← 미표기
```

→ **소속 전환 시점이 목록에서 그대로 역산됩니다.** 금지 요소 "정확한 입·퇴사일"의 취지를 우회로 침해합니다.

| 안 | 내용 | 얻는 것 / 잃는 것 |
|:--:|---|---|
| **A (기본 권고)** | **`org` 전면 미표기** — 15건 모두 회사명 없음 | 전환 시점 역산 불가. 이미 고객사·프로젝트명이 익명화되어 회사명만 남는 정보 가치는 낮음. 익명화 원칙과 정합 |
| B | 과거 3사만 실명, 현재는 비움 (시안 방향) | 과거 이력의 구체성 확보 / 전환 시점 노출 |
| C | 전부 `(이전 소속)` 같은 익명 라벨 | 무의미 — 비움과 정보량이 같은데 줄만 늘어남 |

**web-design 권고는 A**입니다. 명세는 A 기준으로 썼고, `org` 필드는 스키마에 남기되 **목록·상세 모두에서 렌더하지 않습니다.** B를 택하면 §5-3 메타 줄에 4번째 토큰으로 붙습니다.

### 13-2. 🔴 종료월 비우기 대상 불명확

확정 문구는 *"현재 재직처 미표기 + 종료월 비움"* 인데, 시안 데이터에서 `end`가 없는 항목은 **1건**(진행 중)이고 나머지는 2025.08까지 종료월이 있습니다. 어느 항목의 `end`를 비우는지 확정되지 않았습니다.

- 진행 중 프로젝트 1건만 `end` 없음 → **현재 표기 상태**
- 재직 자체의 종료월을 비우는 것이라면 works에는 재직 기간 필드가 없으므로 **해당 없음**

→ product-planner / 사용자 확인 필요. 명세는 "진행 중 프로젝트 1건만 `end` 없음" 기준으로 작성했습니다.

### 13-3. 빈 상태 → 로드 실패 상태로 교체

시안이 그린 빈 상태(`아직 정리 중이에요` / `작업물은 곧 여기에 올라옵니다.` / `GitHub에서 보기 ↗`)는 **WRITING_GUIDE §6.2 표와 문자 단위로 일치**합니다 — 시안이 가이드를 정확히 읽었습니다 ✅.

**다만 이 상태에 도달할 수 없습니다.** 어떤 필터에서도 결과가 0이 아니고, 11건 미만이면 GNB에서 `/works` 링크 자체가 나오지 않습니다.

실제로 발생 가능한 것은 **데이터 로드 실패**이며, 그건 빈 상태가 아니라 에러입니다(§6.3).

```
목록을 불러오지 못했어요
네트워크 상태를 확인해 주세요.
[다시 시도]
```

- 제목 Pretendard 800 `--fs-2xl`(21px) / 설명 `--fs-md`(15px) `--color-text-secondary`
- `[다시 시도]` 주 버튼: 배경 `--color-accent-fill` · 글자 `--color-accent-onFill` · Pretendard 600 `--fs-md`(15px) · 44px · `--shadow-btn-inset`
- 시안의 빈 상태 마크업(`◇` 글리프 + 중앙 정렬 3요소)은 **그대로 재사용**하고 문구·액션만 교체합니다

### 15-1. 파이프라인

```
public/_works/<slug>.md          ← 본문. 있는 항목만. 날짜 접두 없음, 영문 소문자·하이픈
```

| `type` | ✓ | `work` \| `personal` | 필터 · URL `?type=` |
| `role` | ✓ | 문자열 | 실측 최장 10자 |
| `org` | — | 문자열 | §13-1 결정 전까지 **렌더하지 않음** |

| `relatedPost` | — | 글 slug | `관련 글 보기` |

### 15-3. 정렬

```
1차: start 내림차순 (YYYY-MM 문자열 비교로 충분)
2차: slug 오름차순      ← 타이브레이커 필수
```

`start`가 같은 항목이 **3쌍** 있습니다(`2024-07` 2건, `2025-07` 2건, `2024-10` 2건). 타이브레이커가 없으면 빌드마다 순서와 프리렌더 링크가 흔들립니다 — STEP 3 §10-2와 같은 문제입니다.
